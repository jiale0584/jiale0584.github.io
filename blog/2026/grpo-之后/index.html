GRPO 之后

Created on October 17, 2026

2026

2024 年，DeepSeekMath 提出了群组相对策略优化（Group Relative Policy Optimization，GRPO）。随着 2025 年 DeepSeek-R1 的发布，GRPO 也逐渐成为大语言模型强化学习中最受关注的算法之一。

不过，GRPO 并不是强化学习算法发展的终点。从 2025 年开始，研究人员陆续提出了 DAPO、Dr. GRPO、GSPO、CISPO、SAPO 等改进方法。到了 2025—2026 年，随着强化学习逐渐从数学推理、代码生成等相对简单的任务扩展到多轮 Agent，GiGPO、HGPO、G2PO 等面向长轨迹训练的方法也相继出现。

一、回顾 GRPO

在 GRPO 出现之前，大语言模型的强化学习训练主要借鉴近端策略优化（Proximal Policy Optimization，PPO）。

PPO 的一个重要特点是通过裁剪策略更新幅度，避免模型在单次优化中发生过大的变化。不过，在常见的 PPO 训练框架中，我们还需要训练一个价值模型（Value Model），用于估计不同状态下的预期回报，并进一步计算优势（Advantage）。

对于大语言模型而言，这意味着除了策略模型（Policy Model），还需要额外维护一个价值网络。这不仅会增加显存和计算开销，也带来了价值函数估计不准确的问题。

GRPO 的重要贡献，就是尝试摆脱对独立价值模型的依赖。

它的思路并不复杂：对于同一个问题，不再只生成一个回答，而是让当前策略生成一组回答，再根据这些回答的奖励进行组内比较。

假设对于某个问题，我们生成了四个回答，得到的奖励分别为：

R=(1,1,0,0) R=(1,1,0,0) R=(1,1,0,0)

其中，1 表示回答正确，0 表示回答错误。

GRPO 使用组内奖励构造相对优势：

A^i=Ri−RˉσR \hat A_i=\frac{R_i-\bar R}{\sigma_R} A^i​=σR​Ri​−Rˉ​

这里，Rˉ\bar RRˉ 表示这组回答的平均奖励，σR\sigma_RσR​ 表示奖励的标准差。实际实现通常还会在分母加入一个很小的常数，以避免数值问题。

这样一来，高于组内平均奖励的回答会得到正优势，低于平均奖励的回答则得到负优势。模型可以通过组内比较判断哪些行为应该加强、哪些应该抑制，而不必再专门训练一个价值模型。

当然，GRPO 并没有完全抛弃 PPO。它仍然继承了 PPO 的重要性采样（Importance Sampling）以及策略裁剪（Policy Clipping）机制，用于控制新旧策略之间的差异。它主要改变的是优势估计方式，而不是从头建立一套完全不同的强化学习理论。

因此，我们可以将 GRPO 理解为一种基于组内相对奖励、减少独立价值模型依赖的策略优化方法。

但是，这种设计也产生了新的问题。

二、GRPO 存在的问题

1. 长度偏差与难度偏差

要理解这个问题，我们需要先回顾 GRPO 是怎样构造损失函数的。

在监督微调（Supervised Fine-Tuning，SFT）中，模型可以根据标准答案计算交叉熵损失，并通过梯度下降提高正确 Token 的生成概率。但是，GRPO 并没有逐个 Token 的标准答案，而是针对同一个问题生成多个回答，再根据每条回答的最终奖励计算组内相对优势。

对于具有正优势的回答，我们希望模型提高生成这些 Token 的概率；对于具有负优势的回答，则希望模型降低相应的概率。

那么如果我们已经知道应该提高或者降低哪些行为的概率，具体应该怎样更新模型参数，又该如何避免一次更新的幅度过大？

为此，GRPO继承了 PPO 的重要性采样比率（Importance Sampling Ratio）和裁剪机制（Clipping Mechanism）。

首先是重要性采样比率。

在强化学习训练中，我们通常先使用某个策略生成一批回答，再利用这些回答更新模型参数。随着训练进行，正在优化的策略与生成这些回答时使用的策略可能已经不同。

因此，我们需要比较新旧策略对同一个 Token 分配的概率：

ri,t(θ)=πθ(oi,t∣hi,t)πold(oi,t∣hi,t) r_{i,t}(\theta)= \frac{\pi_\theta(o_{i,t}\mid h_{i,t})} {\pi_{\mathrm{old}}(o_{i,t}\mid h_{i,t})} ri,t​(θ)=πold​(oi,t​∣hi,t​)πθ​(oi,t​∣hi,t​)​

其中，πold\pi_{\mathrm{old}}πold​ 是生成这批训练样本时使用的旧策略，πθ\pi_\thetaπθ​ 是当前正在更新的策略，oi,to_{i,t}oi,t​ 表示第 iii 条回答中的第 ttt 个 Token，hi,th_{i,t}hi,t​ 则表示生成该 Token 时的上下文。ooo 表示 output，hhh 表示 history。

例如，假设旧策略生成某个 Token 的概率为 0.1，而新策略将这个概率提高到了 0.15，那么：

ri,t(θ)=0.150.1=1.5 r_{i,t}(\theta)=\frac{0.15}{0.1}=1.5 ri,t​(θ)=0.10.15​=1.5

这意味着新策略生成该 Token 的概率是旧策略的 1.5 倍。如果比率等于 1，说明概率没有变化；如果小于 1，则说明概率有所降低。

假设某个回答获得了正优势，模型在训练时就会尝试提高其中 Token 的生成概率。但如果某一次更新使概率从 0.1 直接提高到 0.5，那么重要性比率就会达到 5。

这样的更新可能过于激进。毕竟，我们对回答的评价来自有限的采样和奖励，并不能保证某个行为在所有情况下都是有益的。如果模型过度强化少数行为，就可能使策略分布发生剧烈变化，影响训练稳定性。

因此，PPO 和 GRPO 引入了裁剪机制，用来限制某些过度更新继续获得优化收益。

其核心是裁剪函数：

clip⁡(r,1−ϵ,1+ϵ) \operatorname{clip}(r,1-\epsilon,1+\epsilon) clip(r,1−ϵ,1+ϵ)

其中，ϵ\epsilonϵ 是控制裁剪范围的超参数。假设 ϵ=0.2\epsilon=0.2ϵ=0.2，裁剪区间就是 [0.8,1.2][0.8,1.2][0.8,1.2]。

对于超过区间上界的比率，裁剪函数返回 1.2；对于低于下界的比率，则返回 0.8；位于区间内部的比率保持不变。

不过，PPO 并不是直接强制新旧策略的概率比永远处于这个区间，而是通过以下目标函数控制更新：

Ji,t(θ)=min⁡(ri,t(θ)A^i,  clip⁡(ri,t(θ),1−ϵ,1+ϵ)A^i) J_{i,t}(\theta)= \min\left( r_{i,t}(\theta)\hat A_i,\; \operatorname{clip}(r_{i,t}(\theta),1-\epsilon,1+\epsilon)\hat A_i \right) Ji,t​(θ)=min(ri,t​(θ)A^i​,clip(ri,t​(θ),1−ϵ,1+ϵ)A^i​)

这里，A^i\hat A_iA^i​ 是第 iii 条回答的优势。我们希望最大化这一目标，因此实际使用梯度下降训练时，需要对它取负号。

假设某个 Token 具有正优势 A^i=1\hat A_i=1A^i​=1，重要性比率已经达到 1.5。那么，未裁剪的目标值是 1.5，而裁剪后的目标值是 1.2。取最小值后，实际目标就停留在 1.2。

此时，即使模型继续提高这个 Token 的概率，也不会进一步增加这一项的目标值。因此，在超出上界的区域，该样本项不再产生推动概率继续上升的梯度。

负优势的情况则相反。假设 A^i=−1\hat A_i=-1A^i​=−1，重要性比率已经下降到 0.5，那么：

min⁡(−0.5,−0.8)=−0.8 \min(-0.5,-0.8)=-0.8 min(−0.5,−0.8)=−0.8

这意味着，当概率比低于裁剪区间的下界后，这个样本项也不再产生推动概率继续下降的梯度。

由此可见，裁剪机制并不是简单地禁止概率发生较大变化，而是使过度强化正优势行为、过度抑制负优势行为的更新不再获得额外收益，从而提高训练的稳定性。

理解了重要性采样比率和裁剪机制之后，我们就可以写出 GRPO 的 Token 级损失项：

其中，TiT_iTi​ 表示第 iii 条回答的 Token 数量。这里暂时忽略 KL 正则化等其他项，只考虑与长度偏差相关的策略优化部分。

Li=∑t=1Tiℓi,t L_i=\sum_{t=1}^{T_i}\ell_{i,t} Li​=t=1∑Ti​​ℓi,t​

注意，1/Ti1/T_i1/Ti​ 已经包含在每个 Token 的损失项中，因此求和时不需要再次除以回答长度。

那么，为什么原始 GRPO 要引入 1/Ti1/T_i1/Ti​？

原因在于，不同回答包含的 Token 数量不同，如果直接将所有 Token 的损失项相加，较长回答就会包含更多参与求和的项。

例如，假设两条回答分别包含 10 个和 100 个 Token，并且在没有长度归一化时，每个 Token 的损失贡献都等于 0.1，那么直接求和得到的损失分别为 1 和 10。

虽然每个 Token 的损失贡献完全相同，但较长回答的损失总和却是较短回答的十倍。为了避免回答长度直接影响损失的数值规模，原始 GRPO 使用回答自身的长度进行归一化。这样，上述两个回答的平均损失都会变成 0.1。

然而，这种处理又产生了新的问题。

对前面定义的重要性采样比率先取自然对数，再对模型参数 θ\thetaθ 求导并整理，可以得到：

∇θri,t(θ)=ri,t(θ)∇θlog⁡πθ(oi,t∣hi,t) \nabla_\theta r_{i,t}(\theta) = r_{i,t}(\theta) \nabla_\theta\log\pi_\theta(o_{i,t}\mid h_{i,t}) ∇θ​ri,t​(θ)=ri,t​(θ)∇θ​logπθ​(oi,t​∣hi,t​)

我们可以暂时不考虑在裁剪，并假定重要性比率等于 1。于是 GRPO 的梯度可以通过下面这个简化的损失来理解：

ℓ~i,t=−A^iTilog⁡πθ(oi,t∣hi,t) \tilde\ell_{i,t} =-\frac{\hat A_i}{T_i} \log\pi_\theta(o_{i,t}\mid h_{i,t}) ℓ~i,t​=−Ti​A^i​​logπθ​(oi,t​∣hi,t​)

因此，正优势倾向于强化已生成的行为，负优势则倾向于抑制这些行为。

但还需要注意损失函数中的 1/Ti1/T_i1/Ti​。对于单个 Token，其损失项相对于对数概率的导数为：

∂ℓ~i,t∂log⁡πθ(oi,t∣hi,t)=−A^iTi \frac{\partial\tilde\ell_{i,t}} {\partial\log\pi_\theta(o_{i,t}\mid h_{i,t})} =-\frac{\hat A_i}{T_i} ∂logπθ​(oi,t​∣hi,t​)∂ℓ~i,t​​=−Ti​A^i​​

这意味着，在优势相同的情况下，回答长度越大，单个 Token 对应的梯度系数绝对值就越小。

例如，当优势为 1 时，10 个 Token 的回答对应的系数为 −0.1-0.1−0.1，而 100 个 Token 的回答只有 −0.01-0.01−0.01。如果优势为 -1，两个系数则分别变成 0.10.10.1 和 0.010.010.01。

因此，长度归一化不仅改变了损失的计算方式，还使每个 Token 的更新权重受到整条回答长度的影响。

对于具有正优势的回答，较短回答中的每个 Token 会获得更大的正向更新权重；对于具有负优势的回答，较长回答中每个 Token 的负向更新权重则更小。

这种机制可能使模型在某些情况下更积极地强化较短的正确回答，同时对冗长的错误回答施加较弱的逐 Token 惩罚。这便是长度偏差。

除了长度偏差，GRPO 使用奖励标准差对优势进行归一化，也可能造成另一种偏差。

回顾 GRPO 的优势计算：

A^i=Ri−RˉσR \hat A_i=\frac{R_i-\bar R}{\sigma_R} A^i​=σR​Ri​−Rˉ​

其中，Rˉ\bar RRˉ 是组内平均奖励，σR\sigma_RσR​ 是组内奖励标准差。实际实现中还需要处理标准差为零的情况。

为什么要除以标准差？因为不同问题的组内奖励分布可能不同，通过标准化可以使优势具有相对一致的尺度，从而改善训练中的数值稳定性。

但是，这也意味着，不同问题的训练权重会受到各自奖励波动程度的影响。

例如，假设两个问题的某条回答都高于各自的平均奖励 0.2，但第一个问题的奖励标准差为 0.1，第二个问题为 0.4，那么标准化之后，它们的优势分别为：

A^1=0.20.1=2 \hat A_1=\frac{0.2}{0.1}=2 A^1​=0.10.2​=2
A^2=0.20.4=0.5 \hat A_2=\frac{0.2}{0.4}=0.5 A^2​=0.40.2​=0.5

可以看到，虽然两个回答都比各自的组内平均奖励高出 0.2，但由于奖励标准差不同，最终优势却相差四倍。

也就是说，GRPO 实际给予不同问题的训练权重，不仅取决于回答相对于组内平均奖励的表现，还取决于该问题的组内奖励分布。

对于只有正确与错误两种奖励的任务，这个问题更加明显。由于组内奖励标准差与成功比例直接相关，当一组回答中只有极少数成功或者只有极少数失败时，标准差通常较小，从而可能放大相应的优势信号。

相比之下，如果一组回答中成功与失败的数量比较接近，其奖励标准差反而较大，优势的缩放程度也就不同。

因此，这里的问题是 GRPO 通过组内奖励波动程度，间接改变了不同任务的训练权重。这也是研究者所说的问题难度偏差。

长度偏差与难度偏差具有一个共同特点：GRPO 原本希望根据奖励来优化模型，但损失归一化和优势标准化又额外引入了与奖励目标不完全一致的加权机制。

2. 组内奖励缺少差异

GRPO 的另一个问题来自组内相对优势本身。

假设我们针对某个问题生成四个回答，结果全部正确：

R=(1,1,1,1) R=(1,1,1,1) R=(1,1,1,1)

此时，所有回答的奖励都等于组内平均值，中心化后的优势全部为零。

同样，如果四个回答全部失败：

R=(0,0,0,0) R=(0,0,0,0) R=(0,0,0,0)

也无法得到有效的组内相对优势。

这就意味着，模型即使花费了大量计算资源生成回答，也不一定能够从中获得训练信号。

对于具有明确正确答案的数学推理任务，这个问题尤其容易出现。过于简单的问题可能全部答对，过于困难的问题则可能全部答错。

更重要的是，即使四个回答全部正确，也不能说明它们的质量完全一致。有些回答可能只需要很短的推理，有些则经过大量无效尝试才得到结果。

3. 策略裁剪与探索能力之间的矛盾

GRPO 继承了 PPO 的裁剪机制。

在策略优化过程中，我们通常使用新旧策略的概率比：

rt(θ)=πθ(at∣st)πold(at∣st) r_t(\theta)= \frac{\pi_\theta(a_t\mid s_t)} {\pi_{\mathrm{old}}(a_t\mid s_t)} rt​(θ)=πold​(at​∣st​)πθ​(at​∣st​)​

这里，πθ\pi_\thetaπθ​ 是正在更新的策略，πold\pi_{\mathrm{old}}πold​ 是采样时使用的旧策略，ata_tat​ 表示当前动作，sts_tst​ 表示当前状态。

为了避免策略发生过大的变化，PPO/GRPO 会限制这个概率比的有效更新范围。

但这里存在一个矛盾：强化学习既需要保持训练稳定，也需要鼓励模型探索新的有效行为。

如果裁剪过于严格，一些原本概率很低、但实际上能够获得较高奖励的行为，即使偶然被采样到，也可能因为重要性比率过早达到裁剪上界，而无法得到充分强化。由于低概率行为本身就不容易被采样，这种限制可能进一步削弱模型发现和强化新行为的能力。

与此同时，如果模型的概率分布在训练过程中不断向少数常见行为集中，策略熵就可能持续下降，严重时甚至出现熵坍缩（Entropy Collapse）。不过，严格裁剪并不必然导致熵坍缩，它也可能起到限制策略过度变化的作用。真正的问题在于，过于严格的裁剪可能抑制有益探索，使模型难以摆脱已经形成的行为集中趋势。

反过来，如果完全放松裁剪，策略更新又可能变得不稳定。

因此，如何在探索能力与训练稳定性之间取得平衡，成为后续算法改进的另一个重要方向。

4. Token 级优化的稳定性

GRPO 通常在 Token 级别计算重要性比率和裁剪项。对于较短的文本生成，这种方法相对容易控制。但在长推理任务中，一条回答可能包含数千甚至数万个 Token，模型需要根据这些 Token 的概率变化进行策略更新。

问题在于，随着模型参数不断更新，新旧策略对同一个 Token 分配的概率可能发生变化，而且不同 Token 的概率变化程度并不一致。

回顾 GRPO 的重要性比率：

ri,t(θ)=πθ(oi,t∣hi,t)πold(oi,t∣hi,t) r_{i,t}(\theta)= \frac{\pi_\theta(o_{i,t}\mid h_{i,t})} {\pi_{\mathrm{old}}(o_{i,t}\mid h_{i,t})} ri,t​(θ)=πold​(oi,t​∣hi,t​)πθ​(oi,t​∣hi,t​)​

假设这条回答最终获得正优势，并且裁剪区间为 [0.8,1.2][0.8,1.2][0.8,1.2]。那么，第一个 Token 的重要性比率已经超过裁剪上界，其正优势损失项不再提供继续提高概率的梯度；而其他 Token 尚未超过上侧裁剪边界，仍然可以参与正常更新。

实际上，这种差异本身并不必然有问题，因为不同 Token 的生成概率本来就可能发生不同程度的变化。真正值得关注的是，当回答变得很长时，模型需要处理大量不同的重要性比率，其中部分比率可能出现极端值。

当然，GRPO 继承了 PPO 的裁剪机制，可以限制部分过度更新。但这又产生了另一个问题：对于正优势行为，如果重要性比率超过上侧裁剪边界，对应损失项的梯度贡献就会变为零。也就是说，如果完全不加限制，极端重要性比率可能放大梯度波动；而采用严格裁剪，又可能丢失一部分有价值的训练信号。

在长回答中，由于需要处理更多 Token，这些局部概率变化和裁剪现象可能更加复杂，从而影响训练的稳定性。这种问题在混合专家模型（Mixture-of-Experts，MoE）中尤其值得关注。MoE 模型会通过路由机制选择参与计算的专家，而随着模型参数更新，同一个 Token 在新旧策略下激活的专家可能发生变化，进而影响其生成概率和重要性比率。

因此，即使训练样本没有发生变化，模型内部的专家路由变化也可能使新旧策略之间出现较大的局部概率差异，进一步增加 Token 级重要性加权的不稳定性。

归根结底，GRPO 在这里的的问题并不是使用 Token 级梯度本身存在错误，而是它对每个 Token 分别进行重要性加权和裁剪。当部分 Token 的概率比发生剧烈变化时，这种处理方式可能引入较大的梯度噪声，或者使部分更新信号因裁剪而消失。

5. 多轮 Agent 的信用分配问题

前面的问题主要出现在单轮生成任务中。而当强化学习被用于多轮 Agent 时，还会遇到一个更加根本的困难。

假设一个 Coding Agent 需要完成某项代码修复任务，它可能先搜索文件、阅读代码、运行测试，再经过多轮修改，最终提交补丁。假如整条轨迹最终成功，我们当然可以给它一个正奖励。但是，这个奖励究竟应该分配给哪些步骤？

某一步正确定位了错误文件，可能为后续修复奠定了基础；另一步进行了无意义的修改，虽然最终被撤销，却消耗了大量时间和工具调用。

如果直接把整条轨迹的最终奖励分配给所有动作，就可能同时强化那些真正有效的决策和那些无关甚至有害的行为。

这就是强化学习中的信用分配（Credit Assignment）问题。在长周期、多轮交互的 Agent 场景下，由于奖励稀疏、反馈延迟，它变得尤其突出。而GRPO 原本基于完整回答进行组内比较的思路，并不足以自动解决这一问题。

三、GRPO 之后的策略优化与改进

前面已经讨论了 GRPO 在归一化、有效采样、裁剪机制和长序列训练中存在的问题。接下来先介绍沿着 GRPO 发展而来的策略优化与训练改进：Dr. GRPO、DAPO、GSPO、SAPO 和 CISPO。它们分别调整优势与损失归一化、采样流程、重要性加权以及梯度控制方式。

至于面向多轮 Agent 的强化学习，尤其是长轨迹内部的优势估计与信用分配，将在下一部分单独讨论。

1. Dr. GRPO

2. DAPO

Dr. GRPO 解决的是归一化偏差，但真实的大规模强化学习训练还会遇到其他困难：模型可能过早集中于少数行为，生成的大量样本未必能提供有效梯度，长短回答的损失聚合会影响学习效果，而达到生成长度上限的回答又可能被错误惩罚。DAPO（Decoupled Clip and Dynamic sAmpling Policy Optimization）针对的正是这些相互联系的训练问题。 它由字节跳动 Seed 等研究团队在 2025 年提出，包含四项主要技术改进。

2. Dynamic Sampling

3. GSPO

2025 年，Qwen 团队提出了群组序列策略优化（Group Sequence Policy Optimization，GSPO），试图解决 GRPO 在大规模强化学习训练中的稳定性问题。与 Dr. GRPO 关注长度归一化和奖励标准差归一化不同，GSPO 将注意力转向了 GRPO 的重要性采样机制。

前面已经介绍过，GRPO 在 Token 级别计算重要性比率，并分别对各个 Token 进行梯度加权和裁剪。当新旧策略之间的差异扩大时，部分 Token 的重要性比率可能出现极端值，从而放大梯度噪声，或者导致部分训练信号因裁剪而消失。

Qwen 团队进一步指出，这种处理方式还存在一个更加根本的问题：GRPO 通常根据整条回答的最终奖励计算优势，但重要性加权和裁剪却分别发生在每个 Token 上。对于完整回答的离策略更新，单个 Token 的概率比并不能直接代表整个回答的新旧概率分布差异。在长序列训练中，这种不匹配可能引入较大的梯度噪声。

因此，GSPO 提出了一个重要的修改：不再对每个 Token 分别使用重要性比率进行加权和裁剪，而是根据整条回答的新旧策略概率变化，构造统一的序列级重要性比率（Sequence-Level Importance Ratio）。

1. Sequence-Level Importance Ratio

那么，整条回答的重要性比率应该如何计算？

3. MoE Training Stability

这种改进在混合专家模型（Mixture-of-Experts，MoE）的强化学习训练中尤其重要。

MoE 模型并不是每次都激活所有专家，而是通过路由机制（Routing Mechanism）选择部分专家参与计算。随着模型参数更新，即使输入仍然是同一个 Token，前后两次计算时被激活的专家也可能发生变化，导致新旧策略对该 Token 分配的概率出现较大差异。

而由于 GSPO 它主要根据整条回答的概率变化进行重要性加权，而不是分别依赖每个 Token 的局部概率比，因此对个别 Token 的概率波动具有更好的容忍性。

根据 Qwen 团队的实验，在其测试的 MoE 训练中，GSPO 即使不依赖 Routing Replay，也能够保持稳定收敛，并在相同训练计算预算下取得比 GRPO 更好的效果。这也成为 GSPO 被应用于 Qwen3 强化学习训练的重要原因之一。

此外，GSPO 对训练与推理系统之间的差异也具有潜在优势。在大规模强化学习中，负责生成回答的推理引擎与负责更新参数的训练引擎可能使用不同的计算方式或数值精度。传统训练流程往往需要重新计算旧策略概率，以减少两者之间的不一致。GSPO 使用序列级概率比，有望降低这种差异对优化过程的影响，从而简化部分训练流程。

总的来说，GSPO 的核心贡献，是将 GRPO 的重要性加权和裁剪机制从 Token 级转向序列级，使同一条回答中的所有 Token 共享一个经过长度归一化的序列级重要性比率。 这一修改减少了局部概率波动引入的训练噪声，尤其改善了 Qwen 团队在大规模 MoE 强化学习中遇到的稳定性问题。与 Dr. GRPO 修正损失归一化偏差、DAPO 改进采样效率和探索机制不同，GSPO 主要重新设计了策略更新的粒度。

4. SAPO

2025 年，Qwen 团队提出了软自适应策略优化（Soft Adaptive Policy Optimization，SAPO），进一步研究 PPO/GRPO 和 GSPO 中的裁剪机制。

前面已经介绍过，GRPO 在 Token 级别进行硬裁剪，GSPO 则将硬裁剪扩展到了序列级别。虽然两者采用的重要性比率不同，但它们都存在一个共同特点：当重要性比率沿着有利的更新方向超过裁剪边界时，相应的梯度贡献会直接变为零。

DAPO 的 Clip-Higher 虽然放宽了裁剪上界，但并未取消硬裁剪：越过边界后，相关梯度仍会突然归零。SAPO 于是提出另一个问题：是否一定需要一个明确的裁剪边界？能不能让梯度随着策略偏离程度逐渐减弱，而不是突然归零？

1. Soft Gating

先回顾原始 PPO/GRPO 的裁剪机制。假设某个 Token 具有正优势，裁剪区间为 0.8,1.20.8,1.20.8,1.2。当重要性比率为 1.1 时，它仍然能够提供正常的梯度；当重要性比率为 1.19 时，同样如此。但如果重要性比率增加到 1.21，该正优势样本项就会进入裁剪目标的平坦区域，梯度直接变为零。

这种不连续的梯度控制可能产生两个问题：如果裁剪区间设置得太窄，模型会过早失去部分有效训练信号；如果裁剪区间设置得太宽，又可能让偏离旧策略较远的样本产生较大的梯度波动。

GSPO 虽然使用序列级重要性比率，但仍然保留硬裁剪，因此也没有彻底消除这个矛盾。而且，如果某条序列的聚合重要性比率超过裁剪边界，整条序列对应的目标项就可能失去梯度，即使其中某些 Token 与旧策略之间的差异并不大。

SAPO 因此选择了另一种方式：使用连续可微的软门控函数（Soft Gating Function），替代原本的硬裁剪机制。

为什么负优势需要更大的温度？这与语言模型的概率归一化有关。

对于某个上下文，语言模型通过 Softmax 将整个词汇表上的 Logit 转换成概率 πθ(a∣h)=eza∑kezk\pi_\theta(a\mid h)=\frac{e^{z_a}}{\sum_{k}e^{z_k}}πθ​(a∣h)=∑k​ezk​eza​​。其中，zaz_aza​ 表示某个 Token 的 Logit，而分母需要对词汇表中的所有候选 Token 求和。

假设模型生成了一个不理想的 Token，并获得负优势。那么，梯度下降会倾向于降低这个已生成 Token 的概率。但是，由于 Softmax 要求所有候选 Token 的概率之和等于 1，降低某个 Token 的相对概率，也意味着其他候选 Token 的概率可能相应上升。

而其他候选 Token 并不一定都是正确或者有价值的。尤其当词汇表非常大时，负优势对应的更新可能影响大量其他候选 Token，而不只是降低当前错误 Token 的概率。

相比之下，正优势通常是提高某个已生成 Token 的概率，并相对压低其他候选项。Qwen 团队认为，两类更新对模型稳定性的影响并不完全对称，负优势对应的更新可能更加容易引入不稳定性。

因此，SAPO 为负优势设置更大的温度参数，使其平滑权重在重要性比率偏离 1 时下降得更快，从而更严格地控制负优势更新。

那么，SAPO 与前面介绍的 GSPO 又有什么关系？

GSPO 使用整条回答的序列级重要性比率，并在序列级进行硬裁剪。这样有利于避免个别 Token 的极端重要性比率直接造成不稳定，但也存在一个问题：如果整条序列的聚合比率超过裁剪边界，整条序列对应的梯度就可能被抑制。

SAPO 则仍然保留 Token 级的平滑权重。因此，当一条回答中的少数 Token 出现极端重要性比率时，它可以重点削弱这些 Token 的梯度贡献，同时继续利用其他偏离程度较小的 Token。

总的来说，SAPO 的主要贡献，是用连续可微的平滑门控函数替代传统硬裁剪，并根据正负优势设置不同的温度参数，使梯度随着策略偏离程度逐渐衰减。

5. CISPO

2025 年，MiniMax 在 MiniMax-M1: Scaling Test-Time Compute Efficiently with Lightning Attention 中提出了 CISPO（Clipped Importance Sampling-weight Policy Optimization，裁剪重要性采样权重的策略优化）。CISPO 仍然在 Token 级进行优化，但重新设计了重要性采样权重的裁剪方式：它不再依赖 PPO 式裁剪目标中的平坦区域，而是让裁剪后的比率作为梯度权重。

1. 保留超过硬裁剪边界的有效梯度

CISPO 的研究背景与 MiniMax-M1 的长推理强化学习训练有关。MiniMax 团队发现，使用原始 GRPO 训练模型时，模型的长链式思维能力没有得到预期中的改善。经过消融实验，他们将一个重要原因定位到了 PPO/GRPO 的裁剪机制上。

回顾前面介绍过的 GRPO 裁剪目标：

Ji,t(θ)=min⁡(ri,t(θ)A^i, clip⁡(ri,t(θ),1−ϵ,1+ϵ)A^i) J_{i,t}(\theta)= \min\left( r_{i,t}(\theta)\hat A_i,\, \operatorname{clip}(r_{i,t}(\theta),1-\epsilon,1+\epsilon)\hat A_i \right) Ji,t​(θ)=min(ri,t​(θ)A^i​,clip(ri,t​(θ),1−ϵ,1+ϵ)A^i​)

假设某个 Token 具有正优势 A^i=1\hat A_i=1A^i​=1，而其重要性比率已经达到 1.5。如果裁剪上界为 1.2，那么 Ji,t=min⁡(1.5,1.2)=1.2J_{i,t}=\min(1.5,1.2)=1.2Ji,t​=min(1.5,1.2)=1.2，此时，只要重要性比率继续大于 1.2，目标值就保持不变，因此对应的梯度为零。特别是对于那些原本生成概率很低、但能够改善推理过程的 Token，过早裁剪可能限制它们的进一步学习。

MiniMax 团队特别关注一些与反思和推理方向变化有关的 Token，例如 However、Recheck、Wait 和 Aha。这些 Token 有时能够引导模型重新检查自己的推理过程，或者从当前推理路径转向其他方向。但由于它们在基础模型中的生成概率往往较低，一旦强化学习开始提高其概率，重要性比率就可能迅速超过裁剪上界。

这种问题在多次使用同一批 Rollout 数据进行更新时更加明显。假设我们使用旧策略生成了一批回答，然后连续进行多轮梯度更新。第一轮更新之后，某个正优势 Token 的重要性比率可能已经超过裁剪上界。那么，在后续仍然使用这批数据进行的更新中，只要它继续处于裁剪区域，就无法再通过这个样本项获得正向梯度。

CISPO 的核心思路，就是不再通过硬裁剪使整个 Token 的梯度贡献归零，而是直接限制重要性采样权重的大小。

为理解这一区别，我们先回到基本的策略梯度形式。对于第 iii 条回答中的第 ttt 个 Token，如果使用重要性采样修正，可以将策略梯度写成：

问题是，如果重要性比率过大，它就可能放大梯度波动。

3. 沿用 DAPO

值得注意的是，CISPO 很大程度上继承了 DAPO 的设计。它同样采用动态采样（Dynamic Sampling）、Token 级损失聚合（Token-Level Policy Gradient Loss）以及针对超长回答的奖励处理机制。

两者最重要的区别在于裁剪机制。DAPO 通过 Clip-Higher 放宽重要性比率的上侧裁剪限制，使正优势 Token 能够获得更大的强化空间，但超过裁剪边界后，相应的梯度仍然会归零。CISPO 则进一步改变了这一机制：它直接裁剪重要性采样权重，并通过停止梯度操作保留相应 Token 的对数概率梯度，从而避免硬裁剪造成的训练信号丢失。

MiniMax 的实验结果显示，在使用 Qwen2.5-32B-base 进行的对照训练中，CISPO 在 AIME 2024 上取得了优于 GRPO 和 DAPO 的表现，并且使用约一半的训练步数就达到了 DAPO 的相近性能。

因此，CISPO 可以视为在吸收 DAPO 训练设计的基础上，对重要性权重与梯度更新关系进行的一次重要调整。 DAPO 的 Clip-Higher 放宽了硬裁剪的上界，SAPO 用平滑函数使梯度连续衰减，而 CISPO 则直接对重要性权重设限，并借助停止梯度保留 Token 的对数概率梯度。

四、面向多轮 Agent 的强化学习与信用分配

前面介绍的 Dr. GRPO、DAPO、GSPO、SAPO 和 CISPO，主要围绕 GRPO 的归一化偏差、采样效率、策略探索以及训练稳定性进行改进。但是，随着大语言模型强化学习逐渐从数学推理等单轮生成任务扩展到多轮 Agent，研究人员开始面对一个更加根本的问题：一条轨迹最终得到的奖励，究竟应该怎样分配给其中的不同决策？

对于普通的数学推理任务，模型通常只需要针对问题生成一段回答，最后根据答案是否正确获得奖励。虽然这个回答可能包含数千个 Token，但整个过程通常被视为一次完整的生成任务。

而多轮 Agent 的运行方式有所不同。例如，一个 Coding Agent 需要修复某个代码仓库中的 Bug。它可能首先搜索文件、阅读相关代码、运行测试，然后根据报错信息修改程序，最后再次执行测试并提交补丁。每一步动作都会改变后续能够观察到的信息，甚至改变代码仓库本身的状态。

假设这个 Agent 最终成功完成任务，我们当然可以给予奖励 1。但是，成功并不意味着此前的每一步操作都值得强化。例如，Agent 可能先正确定位了错误文件，随后又进行了几次无意义的修改，最后才恢复正确方向并完成修复。如果我们直接将最终奖励分配给轨迹中的所有动作，就可能同时强化真正有效的决策和那些无关甚至有害的行为。

这就是强化学习中的信用分配（Credit Assignment）问题。在多轮 Agent 场景中，由于奖励稀疏、反馈延迟，而且不同动作之间存在复杂的依赖关系，这一问题变得尤其突出。

我们再用数学形式进行说明。

假设一个 Agent 需要经过 TTT 轮交互，每轮观察环境状态 sts_tst​，执行动作 ata_tat​，随后进入新的状态。整条轨迹可以写成：

为了解决这一问题，研究人员开始尝试将 GRPO 的组内相对比较思想从完整轨迹扩展到中间状态与动作。GiGPO、HGPO 和 G2PO 正是在这一方向上逐步提出的不同方法。而 PlanPO 则从另一个角度出发，研究当多条轨迹全部成功时，怎样利用执行效率构造新的学习信号。

1. GiGPO

2025 年，研究人员提出了组中组策略优化（Group-in-Group Policy Optimization，GiGPO），试图在不额外训练价值模型的情况下，为多轮 Agent 构造更细粒度的优势信号。

它的核心思想是：除了在完整轨迹之间进行比较，我们还可以寻找不同轨迹中重复出现的环境状态，对从同一个状态出发的动作进行局部比较。 Group-in-Group 指的是外面是同一任务的完整轨迹组，里面则是从这些轨迹中抽取出来、共享某个环境状态的步骤组。

GiGPO 首先沿用 GRPO 的组内相对优势估计，对同一任务生成的多条完整轨迹进行比较。假设四条轨迹的奖励为 R=(1,1,0,0)R=(1,1,0,0)R=(1,1,0,0)，那么组内优势为 AE=(1,1,−1,−1)A^E=(1,1,-1,-1)AE=(1,1,−1,−1)。这种完整轨迹级优势（Episode-Level Advantage）能够反映任务的整体完成情况，但无法区分同一轨迹内部不同动作的贡献。

因此，GiGPO 在保留这一整体评价的基础上，引入锚点状态分组（Anchor State Grouping），通过比较不同轨迹中从相同环境状态出发的动作，进一步构造步骤级优势（Step-Level Advantage）。最终将两种优势结合，兼顾整条轨迹的完成质量与中间动作的相对表现。

假设两个 Coding Agent 都遇到了同一个测试失败状态：

如果我们能确认两个 Agent 面对的是同一个环境状态，那么就可以将这两个动作放在同一组中比较，而不是只比较整条轨迹。

GiGPO 将这种重复出现的环境状态称为锚点状态（Anchor State）。

GiGPO 的一个重要优点是，它不要求每遇到一个状态就额外生成新的分支。它可以直接利用已有轨迹中自然重复出现的状态，通过分组构造局部优势，因此不需要新增价值网络，也不必为了每个中间状态额外执行 Rollout。

不过，GiGPO 也存在明显的局限。首先，并不是所有环境状态都会重复出现。在长周期 Agent 任务中，不同轨迹可能具有完全不同的执行历史，因此能够用于局部比较的状态组未必足够多。其次，即使两个动作从相同状态出发，后续轨迹的成功与失败也不一定完全由当前动作决定。尤其当奖励只有最终成功或失败两种取值时，GiGPO 的局部优势仍然可能缺乏足够的区分度。

更重要的是，相同的外部环境状态，并不意味着 Agent 面临相同的决策条件。 例如，两个 Coding Agent 可能处于相同的代码仓库状态，但其中一个已经阅读了完整报错信息，另一个却尚未运行测试。即使外部环境相同，两者掌握的历史信息也存在明显差异，直接比较其动作未必合理。

这些问题也成为后续研究继续改进 GiGPO 的主要出发点。

2. HGPO、G2PO 与 PlanPO

2026 年提出的 HGPO（Hierarchy-of-Groups Policy Optimization，分层群组策略优化）主要针对历史上下文不一致的问题。它不再仅仅按照当前环境状态分组，而是进一步考虑此前经历的状态序列，根据历史一致程度构造多个层次的比较组，再对不同层次计算出的优势进行加权组合。这样可以在历史上下文的可比性与可用样本数量之间进行一定的权衡。不过，其本质仍然是对 GiGPO 状态分组机制的进一步改进。

G2PO（Group-Graph Policy Optimization，群组图策略优化）则尝试将多条轨迹中重复出现的状态组织成状态转移图。它首先聚合不同轨迹经过同一状态时的后续回报，以此估计状态价值，再通过比较不同动作所到达的后续状态，以及状态转移带来的价值增量，构造节点级和边级优势。这使它能够在局部动作比较之外，进一步利用多条轨迹之间的结构关系。不过，G2PO 同样依赖重复状态的识别与合并，其实际优势主要来自已有状态分组方法之上的增量设计。

另一个方向是 2026 年提出的 PlanPO（Group Planning-Aware Policy Optimization，群组规划感知策略优化）。它关注的是传统 GRPO 无法区分全部成功轨迹的问题：如果同一任务的多条轨迹最终都成功，那么组内结果优势可能全部为零，但这些轨迹的交互轮数和生成长度却可能不同。PlanPO 因此将执行效率纳入优势构造，通过交互轮数和单轮回答长度区分不同成功轨迹。其基本思想并不复杂，本质上是在最终正确性之外增加了效率评价，而不是从根本上解决了多轮决策的信用分配问题。

需要指出的是，这些后续算法目前尚未展现出成熟、经过充分验证的工业应用价值。 从公开研究来看，它们的实验仍然主要集中在 ALFWorld、WebShop、SciWorld、AppWorld 等受控 Agent 基准上。虽然其中部分环境已经包含多步交互、工具调用和较为复杂的任务，但它们与真实软件工程、开放互联网操作等工业场景仍然存在明显距离。尤其对于依赖共享状态的算法而言，真实任务中状态空间巨大、历史上下文复杂，能否获得足够多可比较的状态，以及由此构造的优势能否稳定改善模型能力，都还缺少充分证据。

与此同时，这些工作的公开引用、社区讨论和工程采用情况也相当有限，至少目前还没有形成类似 DAPO、GSPO、CISPO 那样具有明确大模型训练应用背景和较广泛技术讨论的影响力。因此，对于这些研究，我们只是简单过一下。

五、小结

回顾 GRPO 之后的强化学习算法发展，可以发现，这些方法并不是简单的前后替代关系，而是针对原始 GRPO 在实际训练中暴露出的不同问题，沿着不同方向展开改进。

GRPO 通过组内相对奖励估计优势，减少了对独立价值模型的依赖，使大语言模型的强化学习训练更加简单。但这种设计也带来了新的问题：损失归一化可能引入长度偏差，奖励标准差归一化可能改变不同任务的训练权重；当同组回答全部成功或全部失败时，相对优势可能失去区分度；严格的策略裁剪可能丢失有效梯度，而 Token 级重要性比率的波动又可能影响大规模训练的稳定性。

后续算法正是围绕这些问题逐步展开。Dr. GRPO 重新审视目标函数中的归一化方式，DAPO 从采样、裁剪、损失聚合和超长回答处理等方面改进训练流程，GSPO 将重要性加权与裁剪从 Token 级转向序列级，而 SAPO 和 CISPO 则分别通过平滑梯度控制和裁剪重要性采样权重，探索更加稳定的策略更新方式。

另外，随着大语言模型逐渐从单轮推理扩展到多轮 Agent，强化学习又开始面对更复杂的信用分配问题。GiGPO 尝试将组内相对比较扩展到共享环境状态下的中间动作，后续 HGPO、G2PO 等研究则进一步探索历史上下文和状态转移结构的利用。

因此，从现阶段的发展来看，GRPO 之后的强化学习研究可以理解为两个相互关联的方向：一是如何更加稳定、高效地更新模型，二是如何为复杂任务构造更加准确、有效的学习信号。 前者已经积累了较多工业实践，后者尤其在长周期 Agent 场景中仍然存在大量尚未解决的问题。
