OPSD

Created on September 29, 2026

2026   ·   LLM

前面讨论 SFT、知识蒸馏以及强化学习时，可以发现一个比较明显的矛盾：监督越密集，训练通常越容易，但训练数据越容易脱离模型自己真正会遇到的状态；而训练越贴近模型自己的策略，监督信号往往又越稀疏。

传统的 SFT（Supervised Fine-Tuning，监督微调）以及 Off-Policy Distillation（异策略蒸馏）通常使用已经准备好的高质量轨迹。以传统知识蒸馏为例，Teacher Model（教师模型）和 Student Model（学生模型）是两个不同的模型。教师先生成推理轨迹，学生随后沿着教师生成的轨迹学习。

这种方式的优点非常明显：监督十分密集。对于一条长度为 TTT 的推理轨迹，几乎每一个 token 都可以提供训练信号。但它也存在一个问题：学生训练时看到的是教师会访问到的状态，而真正推理时访问的是学生自己产生的状态。

例如教师生成了一条轨迹 s0→s1→s2→s3s_0\rightarrow s_1\rightarrow s_2\rightarrow s_3s0​→s1​→s2​→s3​，学生在 SFT 中学习的就是这些状态下应该如何继续生成。但真正推理的时候，学生可能走成 s0→s1′→s2′s_0\rightarrow s_1'\rightarrow s_2's0​→s1′​→s2′​。此时 s1′s_1's1′​ 和 s2′s_2's2′​ 很可能根本没有出现在教师生成的训练数据中。学生一旦在某一步发生偏离，后续面对的上下文就会越来越偏离训练分布。

这就是 Distribution Mismatch（分布失配）。如果教师策略为 πT\pi_TπT​，学生策略为 πS\pi_SπS​，那么训练数据主要来自教师访问的状态分布 dπTd_{\pi_T}dπT​​，部署时模型真正面对的却是 dπSd_{\pi_S}dπS​​。一般来说，二者并不相同。

强化学习正好解决了这个问题。无论是 PPO（Proximal Policy Optimization，近端策略优化）还是 GRPO（Group Relative Policy Optimization，组相对策略优化），训练轨迹都由当前模型自己 Rollout。因此，它们天然具有 On-Policy（同策略）的性质：模型就在自己真正会访问到的状态上学习。

但 RL 又走到了另一个极端。对于数学和代码等推理任务，RL 最常见的训练信号是 Verifiable Reward（可验证奖励）。一道数学题最后答案正确，Reward 可能为 111；答案错误，则为 000。代码则可以直接通过测试用例判断是否正确。

问题在于，一条推理可能长达数百甚至数千个 token，而最终只得到一个结果奖励。模型生成了 2000 个 token，最后答案错误，训练系统知道的是这条轨迹失败了。但它却不知道究竟是第 200 个 token、第 800 个 token，还是第 1700 个 token 出现了关键错误。

即使 GRPO 或 PPO 最终会把 Advantage（优势）作用到轨迹中的 token 上，这些 token 获得的信号仍然主要来自整条轨迹最终的 Reward。它并没有一个教师在每一步明确告诉模型：“你在这里应该更倾向于生成什么。”

这就是 Sparse Reward（稀疏奖励）以及它背后的 Credit Assignment（信用分配）问题。

于是我们得到了一个很自然的对照：

SFT / 传统蒸馏：异策略，但监督密集。

RL：同策略，但奖励稀疏。

而 OPSD（On-Policy Self-Distillation，同策略自蒸馏）的目标，就是把这两个方向结合起来：

既保留 RL 的 On-Policy，又获得类似 SFT 的 Dense Supervision（密集监督）。

OPSD

OPSD 最特别的地方在于，它不再需要一个额外、更大的教师模型。而是由同一个 LLM 扮演 Teacher 和 Student。

这和传统 Knowledge Distillation（知识蒸馏）不同。传统蒸馏通常是一个更强的 Teacher Model 指导另一个 Student Model；OPSD 中则是同一个模型在不同条件下扮演两个角色。

Student 只看到原始问题，然后按照当前策略生成自己的 Rollout。Teacher 则是同一个模型，但拥有额外的 Privileged Context（特权上下文），例如已经验证的正确答案、正确推理轨迹或者其他只有训练阶段才能获得的信息。

因此可以把两种角色理解为：

Student = 当前模型 + 原始问题。

Teacher = 当前模型 + 原始问题 + 特权信息。

参数本身并没有因为“教师”和“学生”而变成两个独立模型。真正制造能力差异的是输入信息。

训练过程首先让 Student 自己生成轨迹。假设当前模型生成了

x=(x1,x2,…,xT)x=(x_1,x_2,\ldots,x_T)x=(x1​,x2​,…,xT​)。

这条轨迹完全来自当前 Student Policy，所以它天然是 On-Policy 的。

接下来，Teacher 不重新生成一条自己的完整轨迹，而是沿着学生刚刚实际走过的轨迹进行评价。在每一个位置 ttt，Student 和 Teacher 都看到学生已经生成的前缀 x<tx_{<t}x<t​，区别只是 Teacher 额外拥有特权信息。

这样一来，即使学生已经走到了一个比较奇怪的中间状态，Teacher 依然能够回答一个更有价值的问题：“既然你已经走到这里了，那么下一步应该更倾向于生成什么？”

传统蒸馏是在教师会走到的地方训练学生。OPSD 则是在学生自己真的会走到的地方训练学生。

因此，Distribution Mismatch 被显著减弱了。

OPSD 的训练目标

设 πθ\pi_\thetaπθ​ 表示 Student Policy，也就是只看到原始问题时的模型；πθ+\pi_\theta^+πθ+​ 表示 Teacher Policy，也就是拥有 Privileged Context 的同一个模型。

对于学生自己采样得到的轨迹 x=(x1,…,xT)x=(x_1,\ldots,x_T)x=(x1​,…,xT​)，OPSD 在每一个 token 位置比较 Student 和 Teacher 的预测分布：

LOPSD(θ)=Ex∼πθ[∑t=1TKL(πθ(⋅∣x<t)∥πθ+(⋅∣x<t))]. \mathcal L_{\mathrm{OPSD}}(\theta) = \mathbb E_{x\sim \pi_\theta} \left[ \sum_{t=1}^{T} \mathrm{KL} \left( \pi_\theta(\cdot\mid x_{<t}) \parallel \pi_\theta^{+}(\cdot\mid x_{<t}) \right) \right]. LOPSD​(θ)=Ex∼πθ​​[t=1∑T​KL(πθ​(⋅∣x<t​)∥πθ+​(⋅∣x<t​))].

这个公式其实非常直观。

最外面的 x∼πθx\sim\pi_\thetax∼πθ​ 表示：训练轨迹是当前 Student 自己生成的。 这就是 On-Policy 的来源。

x<tx_{<t}x<t​ 表示模型生成第 ttt 个 token 以前的全部前缀。

πθ(⋅∣x<t)\pi_\theta(\cdot\mid x_{<t})πθ​(⋅∣x<t​) 是 Student 在当前位置对整个 Vocabulary（词表）给出的概率分布，而 πθ+(⋅∣x<t)\pi_\theta^+(\cdot\mid x_{<t})πθ+​(⋅∣x<t​) 则是拥有特权信息的 Teacher 给出的概率分布。

OPSD 希望最小化二者之间的 KL Divergence（Kullback–Leibler Divergence，KL 散度）。

简单来说，就是：

学生已经走到当前位置了，现在让学生的下一 token 分布尽量接近“知道正确答案的自己”。

注意这里优化的并不只是最终答案。对于一条长度为 TTT 的轨迹，几乎每一个位置都可以计算一次 KL 散度，所以监督信号覆盖整条推理轨迹。

这就是为什么 OPSD 被称为 Dense Token-Level Supervision（密集的 Token 级监督）。

而且这里采用的是 Reverse KL（反向 KL），也就是 KL(πstudent∥πteacher)\mathrm{KL}(\pi_{\text{student}}\parallel\pi_{\text{teacher}})KL(πstudent​∥πteacher​)。它衡量的是：Student 当前愿意生成的那些 token，在 Teacher 看来到底合理不合理。由于轨迹本身又来自 Student，这个训练目标天然集中在 Student 真正会访问到的区域。

从 KL 到采样 Token

实际训练时，如果每一个位置都完整计算整个 Vocabulary 上的 KL，会涉及完整的概率分布。OPSD 还可以进一步使用 Student 实际采样出来的 token 对这个目标进行估计。

先固定某一个位置 ttt。为了让式子简单一些，令 Student 的分布为 p(v)=πθ(v∣x<t)p(v)=\pi_\theta(v\mid x_{<t})p(v)=πθ​(v∣x<t​)，Teacher 的分布为 q(v)=πθ+(v∣x<t)q(v)=\pi_\theta^+(v\mid x_{<t})q(v)=πθ+​(v∣x<t​)，其中 vvv 表示 Vocabulary 中任意一个 token。

按照 KL 散度的定义：

KL(p∥q)=∑v∈Vp(v)[log⁡p(v)−log⁡q(v)]. \mathrm{KL}(p\parallel q) = \sum_{v\in V} p(v) \left[ \log p(v)-\log q(v) \right]. KL(p∥q)=v∈V∑​p(v)[logp(v)−logq(v)].

注意这里的 ∑v∈Vp(v)f(v)\sum_{v\in V}p(v)f(v)∑v∈V​p(v)f(v)，本质上就是按照分布 ppp 对 f(v)f(v)f(v) 求期望。因此完全可以把它重新写成：

KL(p∥q)=Ev∼p[log⁡p(v)−log⁡q(v)]. \mathrm{KL}(p\parallel q) = \mathbb E_{v\sim p} \left[ \log p(v)-\log q(v) \right]. KL(p∥q)=Ev∼p​[logp(v)−logq(v)].

因为这里的 ppp 恰好就是 Student Policy，所以可以进一步代回：

KL(πθ(⋅∣x<t)∥πθ+(⋅∣x<t))=Ext∼πθ(⋅∣x<t)[log⁡πθ(xt∣x<t)−log⁡πθ+(xt∣x<t)]. \mathrm{KL} \left( \pi_\theta(\cdot\mid x_{<t}) \parallel \pi_\theta^+(\cdot\mid x_{<t}) \right) = \mathbb E_{x_t\sim\pi_\theta(\cdot\mid x_{<t})} \left[ \log\pi_\theta(x_t\mid x_{<t}) - \log\pi_\theta^+(x_t\mid x_{<t}) \right]. KL(πθ​(⋅∣x<t​)∥πθ+​(⋅∣x<t​))=Ext​∼πθ​(⋅∣x<t​)​[logπθ​(xt​∣x<t​)−logπθ+​(xt​∣x<t​)].

生成第 ttt 个位置时，Student 就按照 πθ(⋅∣x<t)\pi_\theta(\cdot\mid x_{<t})πθ​(⋅∣x<t​) 采出了一个实际 token xtx_txt​。所以我们根本不需要额外再采样，可以直接用 Rollout 中已经产生的 xtx_txt​。 于是单个位置上的 KL 可以用

log⁡πθ(xt∣x<t)−log⁡πθ+(xt∣x<t) \log\pi_\theta(x_t\mid x_{<t}) - \log\pi_\theta^+(x_t\mid x_{<t}) logπθ​(xt​∣x<t​)−logπθ+​(xt​∣x<t​)

来做 Monte Carlo Estimation（蒙特卡洛估计）。

把整条轨迹所有位置加起来，就得到：

LOPSD(θ)≈Ex∼πθ[∑t=1T(log⁡πθ(xt∣x<t)−log⁡πθ+(xt∣x<t))]. \mathcal L_{\mathrm{OPSD}}(\theta) \approx \mathbb E_{x\sim\pi_\theta} \left[ \sum_{t=1}^{T} \left( \log\pi_\theta(x_t\mid x_{<t}) - \log\pi_\theta^+(x_t\mid x_{<t}) \right) \right]. LOPSD​(θ)≈Ex∼πθ​​[t=1∑T​(logπθ​(xt​∣x<t​)−logπθ+​(xt​∣x<t​))].

所以这里的逻辑链其实是： KL 对整个 Vocabulary 求和 → 把求和改写成 Student 分布下的期望 → 用 Student 实际采样出来的 token xtx_txt​ 对这个期望做 Monte Carlo 估计。

于是损失可以写成：

LOPSD(θ)≈Ex∼πθ[∑t=1Tlog⁡πθ(xt∣x<t)−log⁡πθ+(xt∣x<t)]. \mathcal L_{\mathrm{OPSD}}(\theta) \approx \mathbb E_{x\sim\pi_\theta} \left[ \sum_{t=1}^{T} \log \pi_\theta(x_t\mid x_{<t}) - \log \pi_\theta^{+}(x_t\mid x_{<t}) \right]. LOPSD​(θ)≈Ex∼πθ​​[t=1∑T​logπθ​(xt​∣x<t​)−logπθ+​(xt​∣x<t​)].

这一式其实就是上一式在 Student Sampling 下的 Monte Carlo Estimation（蒙特卡洛估计）。

因为轨迹 xxx 本身就是按照 πθ\pi_\thetaπθ​ 采样出来的，所以我们不一定需要对整个 Vocabulary 的所有 token 都进行完整求和，而可以直接观察 Student 实际生成的 xtx_txt​。

对第 ttt 个 token 来说，我们比较两个数：

Student 认为自己刚才生成的 xtx_txt​ 有多大概率，即 log⁡πθ(xt∣x<t)\log\pi_\theta(x_t\mid x_{<t})logπθ​(xt​∣x<t​)；

Teacher 在拥有特权信息以后，认为这个 token 有多大概率，即 log⁡πθ+(xt∣x<t)\log\pi_\theta^+(x_t\mid x_{<t})logπθ+​(xt​∣x<t​)。

如果 Student 非常喜欢某个 token，而 Teacher 在知道正确答案以后认为这个 token 很不合理，那么两者之间的差异就会变大，训练会推动 Student 调整自己的概率分布。

因此第二个公式本质上没有改变 OPSD 的目标，它只是把“比较两个完整概率分布”，转化成了“在 Student 实际采样出来的 token 上估计这种差异”。

这里还有一个很重要的工程优势：Teacher 只负责提供 Target Distribution（目标分布），通常不需要计算梯度，也就是说 Teacher 的输出会被 Stop Gradient（停止梯度）处理。

Student 才是需要 Backpropagation（反向传播）的分支。Teacher 只需要做一次 Forward Pass（前向传播），得到对应位置的概率或者 Log Probability（对数概率），然后把它作为训练目标使用。

这也是为什么 OPSD 相比完整 RL Rollout 可以便宜很多。

OPSD、SFT 与 RL

到这里，就可以重新理解三种方法之间的关系了。

SFT 的核心优势在于 Dense Supervision。教师轨迹中的每一个 token 都可以成为学习目标，但这些轨迹通常来自外部数据、人工数据或者其他模型，因此是 Off-Policy 的。

RL 的轨迹来自模型自己，因此是 On-Policy。但数学、代码等任务中的 Reward 通常只在完整答案结束以后给出，因此监督非常 Sparse。

OPSD 正好处于二者之间。

它让 Student 自己 Rollout，因此继承了 RL 的 On-Policy 属性；与此同时，拥有 Privileged Context 的 Teacher 又能在学生轨迹的每一个位置给出 token-level 的预测分布，因此又拥有 SFT 式的 Dense Supervision。

于是可以得到一个非常清楚的结构：

SFT：Off-Policy + Dense Supervision。

OPSD：On-Policy + Dense Supervision。

RL：On-Policy + Sparse Reward。

这也是 OPSD 在整个 Post-Training（后训练）体系中的位置。

SFT 可以先利用高质量轨迹把模型初始化到一个比较合理的推理分布；随后使用 OPSD，让模型在自己真正会进入的状态上不断吸收已经存在的正确知识；直到教师提供的知识已经不足以继续提升模型，再使用 RL 进行真正的 Exploration（探索）。

换句话说，OPSD 更擅长解决“如何高效学会已经知道的东西”，而 RL 最不可替代的价值在于“如何发现原来不知道的东西”。

这也决定了 OPSD 的能力上限。

由于 Teacher 的优势来自 Privileged Context，如果连拥有这些额外信息的 Teacher 都无法解决问题，那么继续蒸馏已经没有新的知识可以传递。这个时候就需要 RL 通过大量 Rollout、Reward 和 Exploration 去发现新的策略。

因此，一个很自然的后训练流水线就是：

SFT → OPSD → RL。

先利用 SFT 快速建立基本能力，再利用 OPSD 低成本地逼近教师能力，最后只在真正需要突破教师能力边界的时候使用昂贵的 RL。
