## 1. RL的基本分类


![image](/assets/img/posts/llm-rl/image.png)


在进入具体算法之前，先建立一张强化学习（Reinforcement Learning, RL）的方法地图。上图首先把强化学习分为两大类：**Model-Free（无模型强化学习）** 和 **Model-Based（基于模型的强化学习）**。这里的 Model 指的是环境模型，也就是描述执行动作以后环境如何变化的状态转移规律 $P(s'|s,a)$。

Model-Free 方法不显式学习或利用环境的状态转移模型，而是直接从与环境交互得到的经验中学习价值函数或者策略。Model-Based 方法则会显式利用环境模型：这个模型可以事先已知，也可以由智能体通过数据学习得到。拥有环境模型以后，智能体就能够预测不同动作可能导致的后续状态，并利用这些预测进行规划。因此，两条路线最根本的区别在于：**是否显式利用环境的动态模型进行决策。**

Model-Free 内部又可以继续分成三条重要路线：**Value-Based（基于价值）**、**Policy-Based（基于策略）** 和 **Actor-Critic（演员—评论家）**。

Value-Based 方法首先学习价值函数，尤其是动作价值函数 $Q(s,a)$。$Q(s,a)$ 表示在状态 $s$ 下选择动作 $a$，并继续行动以后能够获得的期望回报。当这些动作的价值被估计出来以后，就可以直接选择价值最大的动作，即 $a=\arg\max_a Q(s,a)$。因此，这条路线的核心是：**先判断每个动作有多好，再由价值函数间接得到策略。** Q-Learning、SARSA 和 DQN（Deep Q-Network，深度 Q 网络）都是典型的 Value-Based 方法。

Policy-Based 方法直接学习策略本身。策略通常写作 $\pi_\theta(a|s)$，表示在状态 $s$ 下选择动作 $a$ 的概率，其中 $\theta$ 是策略模型的参数。训练的目标就是直接调整 $\theta$，使能够获得更高长期回报的动作具有更高概率。REINFORCE、TRPO（Trust Region Policy Optimization，信赖域策略优化）和 PPO（Proximal Policy Optimization，近端策略优化）都属于这条路线。

Actor-Critic 则把前两种思想结合起来。**Actor** 对应策略 $\pi_\theta(a|s)$，负责选择动作；**Critic** 对应价值函数 $V(s)$ 或 $Q(s,a)$，负责评价当前状态或者动作。训练时，Critic 提供一个关于动作好坏的估计，Actor 再利用这个估计调整自己的策略。因此 Actor-Critic 的核心结构可以概括为：**Actor 负责决策，Critic 负责提供策略更新所需要的价值信息。** A2C（Advantage Actor-Critic）、A3C（Asynchronous Advantage Actor-Critic）和 SAC（Soft Actor-Critic）都是这一体系中的典型方法。

图中把 **GAE（Generalized Advantage Estimation，广义优势估计）** 也放在 Actor-Critic 一侧，不过需要稍微区分一下：GAE 本身并不是一套完整的强化学习算法，而是一种 **Advantage Estimation（优势估计）** 方法。它经常被 PPO 等 Actor-Critic 算法使用，所以从方法谱系上把它放在这里是合理的，但后面我们会单独讲它到底解决了什么问题。

Model-Based 这一侧则进一步分为两种情况。一种是 **Learn Model**：环境模型本身未知，需要先通过数据学习一个模型，然后利用这个模型预测未来并进行规划。World Models、Dreamer 和 MuZero 属于这条路线。另一种是 **Given Model**：环境规则或者状态转移机制已经能够直接使用，此时重点变成在这个模型上进行搜索和规划，MCTS（Monte Carlo Tree Search，蒙特卡洛树搜索）以及 AlphaGo 所使用的搜索体系都可以放在这一侧理解。

因此，这张图实际上对应着几个连续的问题。首先，**是否需要显式建立环境模型？**这决定了 Model-Free 和 Model-Based。对于 Model-Free 方法，接下来又要问：**是先学习动作的价值，再从价值中得到策略；还是直接优化策略本身？**这就形成了 Value-Based 和 Policy-Based。随后还可以进一步把二者结合起来，用价值函数辅助策略更新，于是形成 Actor-Critic。


而对于后面的大语言模型强化学习，我们真正需要关注的是 **Policy-Based（基于策略）** 以及与它紧密相关的 Actor-Critic 路线。原因在于，大语言模型本身就已经定义了一个策略：给定当前上下文 $s$，模型通过 Softmax 输出下一个 Token 的概率分布 $\pi_\theta(a|s)$。因此，相比先额外学习一个 $Q(s,a)$，再从价值函数间接得到动作，大语言模型更自然的做法是直接调整参数 $\theta$，让能够带来更高 Reward 的 Token 和生成轨迹获得更高概率。

于是问题变成了：我们已经有了一个参数化策略 $\pi_\theta(a|s)$，怎样根据最终获得的 Reward，反过来知道模型参数应该朝哪个方向更新？
这就是 **Policy Gradient（策略梯度）**要解决的问题，而最基础的 Policy Gradient 算法就是 REINFORCE。

## 2. Policy Gradient 

既然大语言模型本身已经定义了策略 $\pi_\theta(a|s)$，接下来的问题就是：**怎样直接调整参数 $\theta$，让高 Reward 的动作更容易被选中？**

Policy Gradient（策略梯度）的目标很直接。设一条完整轨迹为 $\tau=(s_0,a_0,s_1,a_1,\ldots)$，其累计回报为 $R(\tau)$，那么我们希望最大化当前策略下的期望回报：$J(\theta)=\mathbb E_{\tau\sim\pi_\theta}[R(\tau)]$。

问题在于，Reward 通常不是参数 $\theta$ 的一个可以直接求导的函数。模型做出动作之后进入环境，最终得到多少 Reward 取决于整条轨迹。Policy Gradient 的关键，是不去对环境本身求导，而是利用模型对动作给出的概率 $\pi_\theta(a|s)$ 来调整轨迹出现的概率。

最终可以得到最基本的策略梯度形式：$\nabla_\theta J(\theta)=\mathbb E_{\pi_\theta}[\sum_t \nabla_\theta\log\pi_\theta(a_t|s_t)\,G_t]$，其中 $G_t$ 表示从时间步 $t$ 开始能够获得的 Return。

这个公式其实直接说明了训练在做什么。$\nabla_\theta\log\pi_\theta(a_t|s_t)$ 表示“怎样调整参数，才能提高当前动作 $a_t$ 在状态 $s_t$ 下的概率”；再乘上 $G_t$，就意味着这个调整方向会根据最终结果被加权。一个动作之后获得的 Return 越高，就越应该提高它再次出现的概率；Return 越低，就越不应该继续强化这个动作。

REINFORCE（REward Increment = Nonnegative Factor × Offset Reinforcement × Characteristic Eligibility） 就是对这一思想最直接的实现。它先使用当前策略生成一条完整轨迹，等待 Episode 结束以后得到实际 Reward，再计算每个时间步对应的 Return $G_t$，最后按照 $\nabla_\theta\log\pi_\theta(a_t|s_t)G_t$ 更新策略。

因此，REINFORCE 的核心可以概括为：**生成 → 获得 Reward → 用 Reward 给生成过程中的动作加权 → 提高高回报动作的概率。**

这一点和监督学习有一点形式上的相似之处。在普通语言模型训练中，如果某个 Token 是训练数据里的正确答案，我们会提高它的概率；在 REINFORCE 中，并没有一个人直接告诉模型“这个动作就是正确答案”，而是模型自己先采样动作，然后根据最终 Reward 决定这些动作应该被强化多少。

但这里很快会出现一个问题。假设一条轨迹最终得到 Reward $100$，另一条得到 Reward $80$。单纯看绝对 Reward，两条轨迹都很好，于是 REINFORCE 都会提高其中动作的概率。但我们真正想知道的其实不是“这个动作获得了多少 Reward”，而是：**这个动作相比当前策略通常能够做到的水平，到底好多少？**

因此可以引入一个 **Baseline（基线）** $b(s_t)$，将更新中的 $G_t$ 改成 $G_t-b(s_t)$：$\nabla_\theta J(\theta)=\mathbb E[\sum_t\nabla_\theta\log\pi_\theta(a_t|s_t)(G_t-b(s_t))]$。

最常见的选择就是令 $b(s_t)=V^\pi(s_t)$。于是 $G_t-V^\pi(s_t)$ 就是在估计当前动作相对于平均水平的 **Advantage（优势）**。如果 Advantage 为正，就提高当前动作的概率；如果为负，就降低它的概率。

这一步非常关键，因为后面真正推动 PPO 更新的已经不再是单纯的 Reward，而是 Advantage。

不过 REINFORCE 还有一个明显的问题：它必须等待整条轨迹结束以后才能知道 $G_t$。而且完整 Return 会受到后面大量随机事件的影响，即使在同一个状态做出相似动作，不同 Rollout 得到的最终 Reward 也可能差别很大，因此梯度的 Variance（方差）会很高。

于是接下来的问题就变成了：**能不能一边直接优化 Policy，一边再训练一个模型去估计“当前状态大概值多少”，从而更稳定地判断当前动作究竟比平均水平好多少？**

这就进入了 Actor-Critic。

## 3. Actor-Critic

REINFORCE 最大的问题之一，是它必须依赖完整轨迹得到的 Return 来更新策略。这样虽然直接，但梯度方差很大：一条轨迹最后得到的高 Reward，可能来自前面某几个真正关键的动作，也可能只是后续随机结果比较幸运，而 REINFORCE 很难把这些因素区分开。

Actor-Critic 的思路是在 Policy-Based 方法中再加入一个 **Critic（评论家）**。原来的策略模型被称为 **Actor（演员）**，负责根据当前状态 $s_t$ 给出动作分布 $\pi_\theta(a_t|s_t)$；Critic 则学习一个 Value Function（价值函数）$V_\phi(s_t)$，用来估计“从当前状态继续走下去，平均能够获得多少 Return”。因此，Actor 负责做决策，Critic 负责判断当前决策相对于正常水平究竟有多好。


有了 Critic 以后，我们希望判断某个动作 $a_t$ 相对于当前状态下的正常水平究竟有多好，这个量就是 **Advantage（优势）**。

最简单的一步 Advantage Estimate（优势估计）可以写成 $\hat A_t=r_t+\gamma V_\phi(s_{t+1})-V_\phi(s_t)$。

先把这个公式里的每一个部分拆开。下标 $t$ 表示当前时间步；$s_t$ 是执行动作之前的当前状态，$s_{t+1}$ 是执行动作 $a_t$ 以后到达的下一个状态；$r_t$ 是执行这一步动作以后立即获得的 **Reward（奖励）**；$V_\phi$ 是 Critic 学习出来的 **Value Function（价值函数）**，其中 $\phi$ 表示 Critic 自己的模型参数。因此 $V_\phi(s_t)$ 表示 Critic 在行动之前预测“从当前状态 $s_t$ 继续下去，预计最终能获得多少 Return”，而 $V_\phi(s_{t+1})$ 表示走完这一步以后，Critic 对剩余未来回报的估计；$\gamma$ 是 **Discount Factor（折扣因子）**，用于控制未来价值在当前估计中占多大权重；最前面的 $\hat A_t$ 中，$A$ 表示 Advantage，而上面的帽子 $\hat{}$ 表示这只是对真实 Advantage 的**估计值**，因为我们并不知道真正的 $Q(s_t,a_t)-V(s_t)$。

因此可以把公式右边分成两部分来看。$r_t+\gamma V_\phi(s_{t+1})$ 表示：**这一步已经实际拿到的 Reward，加上走到下一状态以后预计还能获得的未来价值。** 这个整体被称为 **TD Target（Temporal Difference Target，时序差分目标）**。而 $V_\phi(s_t)$ 是 Critic 在行动之前对当前状态价值的原始预测。

所以整个式子实际上是在计算：

$\text{新的价值判断}-\text{原来的价值判断}$。

也就是 $\hat A_t=[r_t+\gamma V_\phi(s_{t+1})]-V_\phi(s_t)$。

如果 $\hat A_t>0$，说明这个动作带来的结果比当前状态下的平均水平更好，Actor 就应该提高 $\pi_\theta(a_t|s_t)$；如果 $\hat A_t<0$，则应该降低这个动作的概率。因此 Actor 的更新仍然保持 Policy Gradient 的结构：$\nabla_\theta J=\mathbb E[\nabla_\theta\log\pi_\theta(a_t|s_t)\hat A_t]$。区别只在于，原来的完整 Return $G_t$ 被更加稳定的 Advantage Estimate（优势估计）替代了。




Critic 自己也需要训练。它希望自己的 $V_\phi(s_t)$ 尽量接近新的 TD Target（时序差分目标）： $y_t=r_t+\gamma V_\phi(s_{t+1})$，因此可以最小化类似 $L_{\text{critic}}=(V_\phi(s_t)-y_t)^2$ 的损失。这样就形成了一个循环：**Critic 不断学习怎样更准确地评价状态，Actor 再利用 Critic 给出的 Advantage 改进策略**。

***

Critic 带来的好处主要是降低 Variance（方差）。

如果没有 Critic，REINFORCE 直接拿完整的 $G_t$ 去训练 Actor，那么同一个状态下，不同 rollout 后面发生的随机情况可能差很多，导致 $G_t$ 一会儿很高、一会儿很低，于是 Actor 每个 batch 得到的梯度也会剧烈波动。

引入 Critic 后，我们比较的是“这次结果比当前状态的正常水平好多少”，大量与动作本身无关的整体回报波动会被 $V(s_t)$ 抵消，因此 Actor 的梯度会稳定很多。

但也会引入新的问题。

Critic 会预测 $V_\phi(s_t)$，然后我们用一步 TD 得到 $\hat A_t=r_t+\gamma V_\phi(s_{t+1})-V_\phi(s_t)$。如果 Critic 还没学准，比如它长期把某些状态的价值估高，那么算出来的 $\hat A_t$ 也会长期偏高或偏低。也就是存在 Bias 。最终受影响的是 Actor，因为 Actor 按照 $\hat A_t$ 更新 $\pi_\theta$：Advantage 如果被系统性估错，Actor 的更新方向也会被系统性带偏。

## 4. GAE

这就是 **GAE（Generalized Advantage Estimation，广义优势估计）** 要解决的问题。

先看两个极端。如果只使用一步 TD Error，那么 $\hat A_t=r_t+\gamma V(s_{t+1})-V(s_t)$。它只向未来看一步，因此受到随机轨迹的影响很小，Variance 较低；但它严重依赖 Critic 的 $V(s)$ 是否准确，因此可能具有较大的 Bias。

另一个极端是一直看到 Episode 结束，直接使用 Monte Carlo Return：$\hat A_t=G_t-V(s_t)$。这样使用了实际发生的整条轨迹，减少了对 Critic 未来预测的依赖，因此 Bias 更低；但整条轨迹中的随机性会全部累积进来，Variance 又会显著增加。

GAE 的核心就是在这两者之间做连续的折中。首先定义每一个时间步的一步 TD Error：$\delta_t=r_t+\gamma V(s_{t+1})-V(s_t)$。然后不只使用当前的 $\delta_t$，还把未来的 $\delta_{t+1},\delta_{t+2},\ldots$ 按照指数衰减的权重组合起来：

$\hat A_t^{GAE}=\sum_{l=0}^{T-t}(\gamma\lambda)^l\delta_{t+l}$。

这里新增的 $\lambda\in[0,1]$ 控制我们究竟向未来看多远。越远的 TD Error 会被乘上越小的 $(\gamma\lambda)^l$，因此它们对当前 Advantage 的影响逐渐减弱。



所以 GAE 并没有发明一种完全不同的 Advantage，它真正做的是：通过 $\lambda$ 控制 Advantage Estimate 在“一步 TD”与“完整 Return”之间的位置，从而在 Bias 和 Variance 之间取得平衡。

到这里，REINFORCE → Actor-Critic → GAE 这条线就完整了。REINFORCE 告诉我们可以直接用 Reward 更新 Policy；Actor-Critic 加入 Value Function，开始用 Advantage 判断一个动作相对于平均水平到底好不好；GAE 再解决 Advantage Estimate 本身的 Bias–Variance Trade-off（偏差—方差权衡）。

但还有最后一个问题没有解决：即使我们已经知道应该朝哪个方向更新 Policy，但一次更新到底可以走多远呢？

如果 Policy Gradient 一步走得太大，新的 Policy 可能和旧 Policy 相差非常远，训练会直接失稳。接下来 PPO（Proximal Policy Optimization，近端策略优化）真正解决的，就是这个问题。


## 5. LLM RL 的基本框架

前面讲的 Policy Gradient、Actor-Critic 和 GAE，本质上仍然是经典强化学习中的通用方法。接下来真正需要解决的问题是：**大语言模型究竟怎样被写进这套强化学习框架里？**

关键在于，大语言模型本身就已经是一个 Policy。给定当前上下文，模型通过 Softmax 输出下一个 Token 的概率分布，因此原本强化学习中的“状态—动作—策略”可以非常自然地映射到文本生成过程。

### 1. LLM 强化学习的两大方向

在大语言模型中使用强化学习，主要有两种不同的目标。

第一类是**偏好对齐**。典型路线包括 RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）和 DPO（Direct Preference Optimization，直接偏好优化）。它们关心的问题是：对于同一个 Prompt，人类更喜欢哪个回答？通过这种偏好信息，让模型逐渐产生更符合人类要求的输出。RLHF 通常会先训练一个 Reward Model（奖励模型）来预测人的偏好，再用这个 Reward 去优化 Policy；DPO 则进一步把偏好比较直接转化成训练目标，不再显式训练 Reward Model。

第二类是 **RLVR（Reinforcement Learning from Verifiable Rewards，基于可验证奖励的强化学习）**。这条路线更关注能力本身，尤其是数学、代码、推理和 Agent 等具有明确验证标准的任务。这里的 Reward 不一定来自人的主观偏好，而可以直接来自结果是否正确。例如数学答案是否正确、代码是否通过测试、任务是否成功完成。因为 Reward 可以通过规则或验证器直接计算，所以模型能够通过不断生成、获得反馈、再更新 Policy 来提高这些能力。

两条路线虽然 Reward 的来源不同，但底层结构非常接近：都需要一个生成文本的 Policy，一个用来判断生成结果好坏的 Reward 信号，再根据 Reward 调整 Policy。

### 2. 将文本生成写成 MDP

要把强化学习真正应用到语言模型，首先需要把自回归文本生成重新写成一个 **MDP（Markov Decision Process，马尔可夫决策过程）**。

一条回答的生成过程可以看成一个 Episode。模型每生成一个 Token，就完成一次 State → Action → Next State 的转移。

当前状态可以写成 $s_t=(x,y_1,\ldots,y_{t-1})$。这里 $x$ 是最开始输入的 Prompt，$y_1,\ldots,y_{t-1}$ 是模型到目前为止已经生成的 Token。因此 $s_t$ 表示：**模型在决定第 $t$ 个 Token 之前所看到的完整上下文。**

动作 $a_t$ 就是模型下一步选择的 Token。假设词表大小为 $|V|$，那么 $a_t\in\{1,\ldots,|V|\}$。所以在 LLM 中，每一个 Token 都可以理解为强化学习里的一个 Action。

执行动作以后得到下一个状态：$s_{t+1}=(s_t,a_t)$。也就是把刚刚选择的 Token 接到已有序列后面。因此 LLM 中的 Transition 非常简单，而且基本是确定性的：**选中了哪个 Token，下一状态就是把它接到当前上下文后面。**

Policy 就是语言模型本身：

$\pi_\theta(a_t|s_t)$。

其中 $\theta$ 是大语言模型的参数，$s_t$ 是当前上下文，$a_t$ 是某个候选 Token，而 $\pi_\theta(a_t|s_t)$ 就是模型通过 Softmax 得到的“在当前上下文下选择这个 Token 的概率”。

这也是 LLM 强化学习非常特殊的一点：我们不需要再额外构造一个 Policy Network，因为预训练语言模型本身已经是一个参数化 Policy。强化学习真正要做的，只是继续调整 $\theta$，让能够产生更高 Reward 的 Token 序列获得更高概率。

Reward 则负责评价生成结果。最简单的情况下，一整条回答生成结束以后才得到一次 Reward。例如 RLHF 中，可以由 Reward Model 给完整回答打分；RLVR 中，则可以检查最终答案是否正确。

因此整个过程可以压缩成：

**Prompt + 已生成 Token → 当前 State → LLM 采样下一个 Token → 新 State → 继续生成 → 完整回答 → 获得 Reward → 更新 Policy。**

前面我们讲过的 Policy Gradient，到这里也就有了非常具体的含义：如果某条生成轨迹最终获得了更高 Reward，就提高产生这条轨迹的那些动作的概率；如果 Reward 较低，则降低相应动作的概率。

### 3. RLHF 的基本训练流程

经典 RLHF 可以大致分成几个阶段。

首先是 **SFT（Supervised Fine-Tuning，监督微调）**。Base Model 先在高质量的指令—回答数据上训练，使模型具备基本的指令遵循能力。这个阶段得到的模型通常也会成为之后强化学习的初始 Policy。

接下来训练 **Reward Model（奖励模型）**。对于同一个 Prompt，准备多个回答，让人类判断哪个回答更好，例如得到 $y_w \succ y_l$，其中 $y_w$ 表示 Preferred Response，$y_l$ 表示较差的回答。Reward Model 学习这种偏好关系，最终能够输入一个 Prompt 和 Response，输出一个标量 Reward。

然后进入真正的 RL Optimization。当前 Policy 生成回答，Reward Model 对回答打分，再利用 PPO 或 GRPO 等算法根据 Reward 更新 Policy。

最后继续评估新模型，收集新的失败案例和偏好数据，再进入下一轮训练。


RLVR 的结构与此类似，但 Reward 的来源发生了变化。对于数学、代码等任务，可以直接用 Verifier（验证器）判断答案是否正确，不一定需要训练一个模拟人类偏好的 Reward Model。Policy 依然生成 Rollout，然后根据可验证 Reward 进行优化。

### LLM RL 与经典 RL 的区别

虽然我们可以把文本生成完整映射成 MDP，但 LLM 的强化学习和经典 RL 仍然存在几个很重要的差异。

首先是 **Transition 基本确定**。在机器人或者游戏环境中，执行一个动作以后会进入什么状态可能存在随机性；而在文本生成中，选择 Token $a_t$ 后，下一个 State 基本就是把这个 Token 接到原来的序列后面。因此，环境动力学并不是 LLM RL 中最困难的部分。

第二是 **Reward 通常比较稀疏**。一条回答可能包含数百甚至数千个 Token，但最终只有回答结束以后才得到一个整体 Reward。这就产生了非常重要的 Credit Assignment（信用分配）问题：最终得分很好或者很差，到底应该归因于前面的哪些 Token 或推理步骤？

第三是 **Action Space 很大**。普通 RL 可能只有几个或者几十个 Action，而 LLM 每一步都要面对数万甚至十几万个 Token。不过语言模型并不需要显式遍历所有动作再计算一个 $Q(s,a)$，因为它本身已经直接给出了完整的 Token Probability Distribution，这也是 Policy-Based 方法特别适合 LLM 的原因。

第四是 **KL Constraint（KL 约束）**。强化学习如果只追求 Reward，Policy 很可能逐渐偏离原来的语言模型，甚至找到 Reward Function 中的漏洞。因此训练时通常会限制当前 Policy 与 Reference Policy 之间的距离，让模型在提高 Reward 的同时，不至于把原本已经学到的语言能力彻底破坏。

最后，不同算法对于 Critic 的依赖也不同。PPO 沿用了 Actor-Critic 的思路，需要 Value Function 来估计 Advantage；而 GRPO 则进一步去掉 Critic，通过同一个 Prompt 下多条回答之间的相对 Reward 来构造 Advantage。


## 6. PPO

前面已经把经典强化学习真正映射到了大语言模型上。现在对于一条 LLM Rollout，我们已经可以得到每个动作对应的 Advantage，并据此判断这个 Token 的概率应该提高还是降低。但还剩下一个关键问题：**即使更新方向是正确的，一次 Policy Update 到底可以走多远？**

普通的 Policy Gradient 并没有直接限制策略更新幅度。如果某一个 Batch 恰好产生了很大的梯度，一次更新之后，新 Policy 就可能与生成这批 Rollout 时的旧 Policy 相差很远。这样会带来一个直接的问题：我们正在使用旧 Policy 生成的数据训练一个已经发生巨大变化的新 Policy，这批数据对于新 Policy 的代表性会迅速下降，训练很容易失稳。

在 PPO 之前，TRPO（Trust Region Policy Optimization，信赖域策略优化）已经尝试解决这个问题。它直接约束新旧 Policy 之间的 KL Divergence（Kullback–Leibler Divergence，KL 散度），要求新的 Policy 不要离旧 Policy 太远。这个思路有效，但优化过程需要处理更复杂的二阶信息。PPO（Proximal Policy Optimization，近端策略优化）保留了“不要一次走太远”这个核心思想，但用一个更容易优化的 Clipped Objective（裁剪目标）来实现。

### 1. Probability Ratio

PPO 首先定义新旧 Policy 对同一个动作给出的概率之比：

$r_t(\theta)=\frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_{\mathrm{old}}}(a_t|s_t)}$。

这里的每一个部分都对应着一个非常具体的东西。$s_t$ 是生成这条 Rollout 时第 $t$ 步的 State；$a_t$ 是旧 Policy 当时实际采样出来的 Action；$\pi_{\theta_{\mathrm{old}}}(a_t|s_t)$ 是**生成这批数据时，旧 Policy 对这个动作给出的概率**；$\theta_{\mathrm{old}}$ 表示生成 Rollout 时被冻结下来的旧参数。$\pi_\theta(a_t|s_t)$ 则是当前正在训练的新 Policy，在同一个 $s_t$ 下现在给 $a_t$ 多大的概率；$\theta$ 是此时正在被梯度下降更新的参数。

因此，最外面的 $r_t(\theta)$ 表示的就是：**经过更新以后，新 Policy 对这个动作的概率变成了旧 Policy 的多少倍。**

如果 $r_t=1$，说明这个动作的概率完全没有变化；如果 $r_t=1.2$，说明概率变成了原来的 $1.2$ 倍；如果 $r_t=0.8$，说明只剩原来的 $80\%$。

为什么要看这个 Ratio？因为前面 Advantage 已经告诉了我们**方向**。如果 $\hat A_t>0$，这个动作比平均水平好，我们希望它的概率提高，也就是希望 $r_t>1$；如果 $\hat A_t<0$，说明这个动作比较差，我们希望它的概率降低，也就是希望 $r_t<1$。

于是可以先写出一个还没有裁剪的目标：

$L^{\mathrm{CPI}}(\theta)=\mathbb E_t[r_t(\theta)\hat A_t]$。

其中 $L^{\mathrm{CPI}}$ 是我们希望最大化的 Surrogate Objective（代理目标）；$\mathbb E_t$ 表示对当前 Batch 中所有时间步的样本取平均；$r_t(\theta)$ 表示新旧 Policy 对当前动作概率的变化；$\hat A_t$ 则表示这个动作究竟比平均水平好还是差。

因此 $r_t(\theta)\hat A_t$ 的作用很直观：如果 $\hat A_t>0$，增大 $r_t$ 可以让目标变大，因此优化器会提高这个动作的概率；如果 $\hat A_t<0$，降低 $r_t$ 反而可以让目标变大，于是优化器会降低这个动作的概率。

问题也恰恰出现在这里：**这个目标没有规定 $r_t$ 可以离 1 多远。**

假设某个动作的 $\hat A_t>0$，那么从这个目标本身来看，把 $r_t$ 从 $1.1$ 提高到 $1.5$、$2$ 甚至更大，目标都会继续改善。一个“好动作”可能因此在一次训练中被过度提高概率；一个“坏动作”也可能被一次性压得太狠。这就是 PPO 真正要处理的问题。

### 2. Clipped Objective

PPO 把目标改成：

$L^{\mathrm{CLIP}}(\theta)=\mathbb E_t[\min(r_t(\theta)\hat A_t,\operatorname{clip}(r_t(\theta),1-\epsilon,1+\epsilon)\hat A_t)]$。

先拆第二项里的 $\operatorname{clip}$。$\epsilon$ 是 PPO 的 Clip Range（裁剪范围），例如可以取 $\epsilon=0.2$，那么允许的 Ratio 区间就是 $[0.8,1.2]$。

$\operatorname{clip}(r_t,1-\epsilon,1+\epsilon)$ 的意思是：如果 $r_t$ 本来就在这个区间中，就保持原值；如果高于 $1+\epsilon$，就按 $1+\epsilon$ 计算；如果低于 $1-\epsilon$，就按 $1-\epsilon$ 计算。

但是 PPO 还在外面加了一个 $\min$。它不是简单粗暴地把所有 Ratio 截断，而是在**原始目标 $r_t\hat A_t$**和**裁剪后的目标 $\operatorname{clip}(r_t,1-\epsilon,1+\epsilon)\hat A_t$**之间，选择对策略更新更加保守的那一个。

先看 $\hat A_t>0$。这说明当前动作是一个好动作，我们希望提高它的概率。假设 $\epsilon=0.2$，那么当 $r_t$ 从 $1$ 增长到 $1.1$、$1.15$ 时，目标可以正常增加；但如果 $r_t$ 已经超过 $1.2$，例如达到 $1.5$，裁剪后的那一项仍然只按照 $1.2\hat A_t$ 计算。由于外面取的是 $\min$，继续把 Ratio 从 $1.2$ 提高到 $1.5$ 已经不能再带来额外收益。


到这里，PPO 最核心的思想其实已经出来了。**Advantage 决定更新方向，Probability Ratio 衡量新旧 Policy 对当前动作的变化，而 Clipping 则限制这次变化不要过大。**

因此，从前面的整条路线来看：

Policy Gradient 解决“往哪个方向更新”；Actor-Critic 和 GAE 解决“怎样更稳定地估计这个方向”；PPO 则解决“沿着这个方向一次允许走多远”。

这也正是 **Proximal** 这个词的含义：新的 Policy 应该保持在旧 Policy 的附近。

不过这里还剩下一个非常重要的问题。既然 PPO 的数据是由 $\pi_{\theta_{\mathrm{old}}}$ 生成的，而训练过程中 $\theta$ 会不断发生变化，那么为什么同一批 Rollout 还能被重复训练多个 Epoch？以及 old Policy 到底在这个过程中什么时候更新？

这就涉及 PPO 的 Rollout、old Policy 和 Importance Sampling（重要性采样）。

### 3.  Importance Sampling

先从 **Rollout（轨迹采样）** 开始。强化学习里的 Rollout，指的是 Agent 按照当前 Policy 与环境进行一次完整或部分交互，得到的一段状态—动作—奖励序列。对于大语言模型来说，一条 Rollout 就非常具体：给模型一个 Prompt，然后让它按照当前 Policy 一个 Token 一个 Token 地生成，直到回答结束。

因此，一条 LLM Rollout 可以理解成一条完整的生成轨迹：

$s_0\rightarrow a_0\rightarrow s_1\rightarrow a_1\rightarrow\cdots\rightarrow s_T$。

其中 $s_t$ 是当前 Prompt 加上已经生成的所有 Token，$a_t$ 是第 $t$ 步实际采样出来的下一个 Token。每选择一个新的 Token，就会得到下一个 State，直到整条回答生成完成。

PPO 在 Rollout 阶段并不只是保存最终生成出来的文本，而是会记录训练之后需要使用的信息。对于每一个时间步，通常会保存当前状态 $s_t$、实际选择的动作 $a_t$、生成这个动作时旧 Policy 给出的概率 $\pi_{\theta_{\mathrm{old}}}(a_t|s_t)$，以及 Reward、Value 等之后计算 Advantage 所需要的信息。

这里就自然引出了 **old Policy**。

假设开始这一轮 PPO 时，当前模型参数是 $\theta_{\mathrm{old}}$。我们首先用这个 Policy 生成一批 Rollout。这批 Rollout 一旦生成完成，$\theta_{\mathrm{old}}$ 对应的信息就被固定下来，因为它代表的是：**这批数据当初究竟是由哪个 Policy、以什么概率生成出来的。**

接下来开始训练以后，当前 Policy 的参数 $\theta$ 会不断更新，从 $\theta_{\mathrm{old}}$ 逐渐变成新的参数。但 Rollout 里保存的旧概率 $\pi_{\theta_{\mathrm{old}}}(a_t|s_t)$ 不会跟着改变。

于是对于同一个状态 $s_t$ 和动作 $a_t$，我们现在同时拥有两个概率：一个是当初生成数据时的旧概率 $\pi_{\theta_{\mathrm{old}}}(a_t|s_t)$，另一个是当前新 Policy 重新看这个动作时给出的概率 $\pi_\theta(a_t|s_t)$。

二者的比值就是前面已经见过的 Probability Ratio：

$r_t(\theta)=\frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_{\mathrm{old}}}(a_t|s_t)}$。

它衡量的是：**当前 Policy 相对于生成这批 Rollout 时的 Policy，已经把这个动作的概率改了多少。**

第一次开始训练时，新旧 Policy 几乎完全相同，因此 $r_t\approx1$。随着参数不断更新，同一个动作在当前 Policy 下的概率也会发生变化，$r_t$ 就可能变成 $1.05$、$0.9$、$1.2$ 等。

接下来才需要引入 **Importance Sampling（重要性采样）**。

问题在于，这批 Rollout 是由旧 Policy $\pi_{\theta_{\mathrm{old}}}$ 生成的，但我们现在真正想优化的是新的 Policy $\pi_\theta$。如果完全忽略两者之间的分布差异，直接把旧数据当成当前 Policy 自己生成的数据，就会产生分布不匹配。

Importance Sampling 的基本思想，就是使用概率比 $\frac{\pi_\theta}{\pi_{\theta_{\mathrm{old}}}}$ 对旧数据重新加权。

例如某个动作在旧 Policy 下出现概率是 $10\%$，而当前 Policy 下已经变成 $20\%$，那么 $r_t=2$。这表示如果现在重新按照新 Policy 采样，这类动作出现的频率大约会是旧 Policy 的两倍，因此旧 Rollout 中对应样本在估计新 Policy 目标时也需要相应调整权重。

这也解释了为什么 PPO 可以让**同一批 Rollout 重复训练多个 Epoch**。每训练一轮以后，虽然 Policy 已经发生变化，但我们仍然可以通过新的 $\pi_\theta(a_t|s_t)$ 和固定的旧概率 $\pi_{\theta_{\mathrm{old}}}(a_t|s_t)$ 重新计算 $r_t$，从而修正新旧 Policy 之间的差异。

当然，这种复用不能无限进行。随着训练持续进行，当前 Policy 会越来越偏离 old Policy，越来越多的 $r_t$ 会远离 $1$，这批旧 Rollout 也会越来越不能代表当前 Policy。PPO 的 Clipping 可以限制这种偏移带来的风险，但不能让旧数据永久有效。

因此一批 Rollout 通常只训练有限几个 Epoch。训练结束后，这批数据就被丢弃；更新后的当前 Policy 成为下一轮新的 old Policy，再重新生成下一批 Rollout。
***


随着当前 Policy 不断更新，它会逐渐偏离生成这批 Rollout 时的 old Policy。Importance Sampling 通过概率比 $r_t(\theta)=\frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_{\mathrm{old}}}(a_t|s_t)}$ 修正这种分布差异，因此同一批 Rollout 可以被重复利用几个 Epoch；而前面讲过的 Clipping 又会在 $r_t$ 偏离 $1$ 太远时限制继续更新，避免旧数据被过度利用。

于是，PPO 对 **Actor** 的核心更新逻辑到这里就完整了：old Policy 负责生成 Rollout，Importance Sampling 让这些旧数据可以用于当前 Policy，Advantage 决定动作概率应该提高还是降低，Clipping 则限制同一批数据把 Policy 推得过远。训练若干 Epoch 后，这批 Rollout 已经越来越不能代表当前 Policy，就将其丢弃，再用更新后的 Policy 生成下一批数据。

### 4. Rollout Buffer

PPO 在生成 Rollout 以后，需要把这一轮训练会用到的信息暂时保存下来，这个临时存储结构就是 **Rollout Buffer（轨迹缓冲区）**。

对于每一个时间步 $t$，Rollout Buffer 通常会记录 $s_t$、$a_t$、$\log\pi_{\theta_{\mathrm{old}}}(a_t|s_t)$、$r_t$ 和 $V_\phi(s_t)$。

这里 $s_t$ 是当前 State，$a_t$ 是实际采样出的 Action；$\log\pi_{\theta_{\mathrm{old}}}(a_t|s_t)$ 是 old Policy 当时给这个动作的 Log Probability，之后计算 Probability Ratio 时需要；$r_t$ 是 Reward；$V_\phi(s_t)$ 是 Critic 对当前状态的 Value Estimate，之后计算 GAE Advantage 时需要。

之所以要专门保存这些信息，是因为 PPO 的训练和 Rollout 是分开的：先集中生成一批轨迹，再拿这一批固定的数据训练若干 Epoch。训练过程中当前 Policy 会不断变化，但 old Policy 的概率、Reward 和当时对应的状态动作都必须保持不变，因此需要先把它们存下来。

Rollout Buffer 的生命周期也很短。它通常经历三个阶段：

**生成 Rollout → 填满 Buffer → 用这批数据训练若干 Epoch → 清空 Buffer → 用新 Policy 重新生成。**


### 5. PPO 的完整训练目标

PPO 并不只有 Actor。前面讲完的是 PPO 怎样训练 Policy；接下来还需要把 Critic 的训练以及整个 PPO Objective 补完整。

PPO 作为 Actor-Critic 方法，实际训练时同时维护两个目标：一边更新 Actor，让高 Advantage 的动作概率提高、低 Advantage 的动作概率降低；另一边更新 Critic，让 $V_\phi(s)$ 对状态价值的预测越来越准确。此外，通常还会加入 Entropy Bonus（熵奖励），避免 Policy 在训练早期过快集中到少数动作上。

于是完整目标才写成：

$L(\theta,\phi)=L^{\mathrm{CLIP}}(\theta)-c_1L^{VF}(\phi)+c_2H[\pi_\theta]$。

这个公式里三部分分别负责三件不同的事，因此不能把它当成一个整体硬记。先看第一项 $L^{\mathrm{CLIP}}(\theta)$。这里的 $\theta$ 是 Actor，也就是当前 Policy 的参数。这一项就是前面已经讲过的 Clipped Objective，它根据 Advantage 调整动作概率：$\hat A_t>0$ 时提高该动作的概率，$\hat A_t<0$ 时降低该动作的概率，同时用 Probability Ratio 和 Clipping 防止一次更新走得太远。因此这一项负责的就是 **Policy Optimization（策略优化）**。

第二项 $L^{VF}(\phi)$ 是 **Value Function Loss（价值函数损失）**，负责训练 Critic。这里的 $\phi$ 是 Critic 的参数，而 Critic 输出的 $V_\phi(s_t)$ 表示：从状态 $s_t$ 开始，按照当前 Policy 继续行动，预计还能得到多少 Return。为了让这个预测越来越准确，需要给它一个训练目标 $V_t^{\mathrm{target}}$，最基本可以写成 $L^{VF}(\phi)=\mathbb E_t[(V_\phi(s_t)-V_t^{\mathrm{target}})^2]$。

这里每一部分的意义都很直接。$V_\phi(s_t)$ 是 Critic 当前的预测，$V_t^{\mathrm{target}}$ 是根据 Rollout 得到的更可信的目标值；两者做差表示 Critic 预测错了多少，再平方是为了让正负误差都变成正数，并且对较大的预测误差给予更大的惩罚。最终通过最小化这一项，Critic 就会逐渐学会更准确地估计 State Value。



公式前面的 $c_1$ 则是一个权重系数。因为 Policy Objective 和 Value Loss 的数值尺度可能完全不同，如果直接相加，其中一项可能远远盖过另一项，所以用 $c_1$ 控制 Critic Loss 在整个训练目标中的影响程度。

最后一项 $H[\pi_\theta]$ 是 **Policy Entropy（策略熵）**，它衡量的是 Policy 的概率分布有多分散。定义可以写成 $H[\pi_\theta(\cdot|s_t)]=-\sum_a\pi_\theta(a|s_t)\log\pi_\theta(a|s_t)$。

这里的 $a$ 表示当前状态下所有可能的 Action；$\pi_\theta(a|s_t)$ 是每个动作对应的概率；求和表示把整个动作概率分布都考虑进去。Entropy 越高，说明概率分布越分散，Policy 仍然会尝试多种不同动作；Entropy 越低，说明概率越来越集中到少数动作上。

为什么 PPO 要保留一定的 Entropy？因为 Policy Gradient 会不断提高高 Advantage 动作的概率。如果训练早期某个动作只是偶然得到了很高 Reward，模型却迅速把概率全部集中到这个动作上，那么之后其他动作几乎不会再被采样，模型也就失去了继续探索更优策略的机会。这种现象通常称为 **Premature Policy Collapse（策略过早坍缩）**。

因此 $+c_2H[\pi_\theta]$ 相当于给“仍然保留一定探索性”的 Policy 一个小奖励。这里的 $c_2$ 同样是权重系数，用来控制 Entropy Bonus 的强度。$c_2$ 太大，Policy 会保持过多随机性，难以真正收敛；$c_2$ 太小，则几乎无法阻止概率分布快速集中。

最后再看整个式子的正负号：

$L(\theta,\phi)=L^{\mathrm{CLIP}}(\theta)-c_1L^{VF}(\phi)+c_2H[\pi_\theta]$。

这里我们把 $L$ 写成了一个**需要最大化的 Objective**。因此 $L^{\mathrm{CLIP}}$ 越大越好；Entropy 作为 Bonus，也是越大越有利；而 $L^{VF}$ 是误差，显然越小越好，所以前面要加负号 $-c_1L^{VF}$。

如果实际代码采用的是“最小化 Loss”的写法，那么通常会把符号整体翻过来，例如写成 $-L^{\mathrm{CLIP}}+c_1L^{VF}-c_2H$。两种写法看上去符号相反，但优化方向完全一致。

因此 PPO 的完整训练目标其实同时维护三个东西：**Actor 根据 Advantage 改进 Policy；Critic 学习更准确的 Value Function；Entropy Bonus 防止 Policy 太早失去探索性。**

这样，一轮 PPO 的完整过程就可以串起来了：先用当前 Policy 生成 Rollout，Reward Model 或环境给出 Reward，Critic 给出 Value Estimate，再通过 GAE 得到 Advantage；随后用 old Policy 与当前 Policy 计算 Probability Ratio，通过 Clipped Objective 更新 Actor，同时通过 Value Loss 更新 Critic，并用 Entropy Bonus 保留一定探索性；同一批 Rollout 训练若干 Epoch 以后丢弃，再用新的 Policy 重新生成下一批数据。

到这里，PPO 的算法主体就基本完整了。下一步比较自然的是进入 **PPO 在 LLM RLHF 中的实际结构**：Policy Model、Reference Model、Reward Model 和 Value Model 四个模型分别干什么，以及一条生成出来的 Response 最终是怎样变成 Token 级训练信号的。

### 6. PPO 在 RLHF 中的完整流程

前面已经把 PPO 本身的算法机制拆开了。放回大语言模型的 RLHF 中，一轮训练通常可以理解为四个核心组件协同工作：**Policy Model、Reference Model、Reward Model 和 Value Model**。它们虽然可能共享相同或相近的模型结构，但在训练过程中承担的任务完全不同。经典 RLHF 的基本流程就是先由 Policy 生成回答，由 Reward Model 给回答提供奖励，再利用 PPO 更新 Policy，同时通过 KL 约束限制其偏离参考策略。

Policy Model（策略模型）就是我们真正想训练的大语言模型，记作 $\pi_\theta$。给定 Prompt 和已经生成的 Token，它输出下一个 Token 的概率分布，并按照这个分布不断采样，最终得到完整 Response。PPO 最终更新的主要对象就是它的参数 $\theta$。

Reward Model（奖励模型）负责回答“这条 Response 到底有多好”。Policy 完整生成一条回答以后，Reward Model 输入 Prompt 和 Response，输出一个标量 Reward $r_{\mathrm{RM}}$。这个分数提供了强化学习真正需要优化的方向，但它通常评价的是整条回答，并不能直接告诉我们某一个具体 Token 应该承担多少 Credit。

Value Model（价值模型，也就是 Critic）**负责预测每一个 Token 位置上的 State Value $V_\phi(s_t)$。前面已经讲过，GAE 会利用这些 Value Estimate 将最终 Reward 转化成每个位置对应的 Advantage $\hat A_t$，从而回答：“第 $t$ 个 Token 相对于当前策略的正常水平，究竟贡献得更好还是更差？”

最后还有一个非常重要的Reference Model（参考模型），通常记作 $\pi_{\mathrm{ref}}$。它通常来自强化学习开始之前的 SFT Model，并在 RL 阶段保持冻结。它的作用是给当前 Policy 提供一个锚点：Policy 可以为了获得更高 Reward 改变自己的输出分布，但不能无限远离原本已经具有良好语言能力和指令遵循能力的模型。LLM RL 中加入 KL 约束正是为了限制这种偏移。

这里必须把 Reference Model 和前面 PPO 的 **old Policy** 区分开。old Policy $\pi_{\theta_{\mathrm{old}}}$ 是当前这一轮 Rollout 开始时 Policy 的临时快照，它用于计算 Probability Ratio $r_t=\frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_{\mathrm{old}}}(a_t|s_t)}$，一轮 PPO 结束以后就会被新的 Policy 替换。而 Reference Model $\pi_{\mathrm{ref}}$ 是整个 RLHF 训练中的长期锚点，通常始终冻结，用于判断 Policy 已经偏离原始 SFT Model 多远。

于是，一轮真正的 LLM PPO 可以从生成开始。

首先，Policy Model 对一批 Prompt 生成 Response，形成 Rollout。在第 $t$ 个 Token 位置，当前 State 是 $s_t$，实际生成的 Token 是 $a_t$，同时保存 old Policy 当时给这个 Token 的 $\log\pi_{\theta_{\mathrm{old}}}(a_t|s_t)$，以及 Critic 给出的 $V_\phi(s_t)$。

完整回答生成以后，Reward Model 给出回答层面的 Reward $r_{\mathrm{RM}}$。但 RLHF 通常不会直接把这个 Reward 原封不动交给 PPO，因为 Policy 还有可能通过不断偏离原始语言模型来“钻 Reward 的空子”。因此还需要计算当前 Policy 与 Reference Model 的差异。

对于实际生成的 Token $a_t$，可以比较二者的 Log Probability：

$\mathrm{KL}_t=\log\pi_\theta(a_t|s_t)-\log\pi_{\mathrm{ref}}(a_t|s_t)$。

这里 $\pi_\theta(a_t|s_t)$ 是当前 Policy 给生成 Token 的概率，$\pi_{\mathrm{ref}}(a_t|s_t)$ 是 Reference Model 对同一个 Token 给出的概率。两者越接近，这个差值越小；如果当前 Policy 开始大量生成 Reference Model 原本认为非常不可能的 Token，差值就会增大。

于是最终优化使用的 Reward 可以理解成：

$R=r_{\mathrm{RM}}-\beta\,\mathrm{KL}$。

这里 $r_{\mathrm{RM}}$ 是 Reward Model 给出的任务奖励，$\mathrm{KL}$ 衡量当前 Policy 偏离 Reference Model 的程度，而 $\beta$ 是 **KL Coefficient（KL 系数）**，控制我们究竟愿意用多大的 Policy 偏移去换取 Reward。第一项要求“回答越来越好”，第二项要求“不要为了提高分数把原来的模型彻底改坏”。

得到最终 Reward 以后，就轮到 Critic 和 GAE。Critic 已经为不同 Token 位置预测了 $V_\phi(s_t)$，GAE 再结合 Reward 与这些 Value Estimate，为每一个 Token 得到 Advantage $\hat A_t$。于是原来只有整条 Response 一个整体分数的问题，被转化成了 Token 级的训练信号：哪些 Token 相对于预期表现更好，哪些更差。

接下来进入真正的 PPO Update。对每一个 Token，重新用当前 Policy 计算 $\pi_\theta(a_t|s_t)$，再和 Rollout 时保存的 old Policy 概率比较，得到 $r_t(\theta)=\frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_{\mathrm{old}}}(a_t|s_t)}$。随后把 $r_t$ 和 $\hat A_t$ 代入前面已经讲过的 Clipped Objective，更新 Actor；与此同时，用 Value Loss 更新 Critic，并通过 Entropy Bonus 保留一定探索性。

所以到这里，PPO 在 LLM 中的位置就完整了。它本身并不负责创造 Reward，也不负责定义“什么回答是好的”；它负责的是：在已经获得 Reward 和 Advantage 以后，怎样稳定地把这些反馈转化成对语言模型参数的更新。

## 7. DPO

前面的 PPO-RLHF 已经说明了一套完整的偏好对齐流程：先让 Policy 生成 Rollout，再由 Reward Model 给回答打分，Reference Model 提供 KL 约束，Critic 和 GAE 计算 Advantage，最后再通过 PPO 更新 Policy。问题也很明显：**如果我们手里最初拥有的信息本来就是“对于同一个 Prompt，人更喜欢回答 A 而不是回答 B”，有没有可能直接利用这个偏好关系训练 Policy，而不再先训练 Reward Model、再跑一整套强化学习？**

这就是 DPO（Direct Preference Optimization，直接偏好优化）提出的问题。它最核心的想法是：RLHF 中“最大化 Reward，同时通过 KL Constraint 限制 Policy 不要离 Reference Model 太远”这个优化问题，其最优 Policy 可以写出解析形式。既然 Reward 与最优 Policy 之间存在明确的数学关系，就可以把 Reward 从中消掉，最终直接得到一个只依赖 **Preference Data（偏好数据）**、当前 Policy 和 Reference Policy 的监督式 Loss。

### 1. Preference Data

DPO 的一条训练数据通常写成 $(x,y_w,y_l)$。

其中 $x$ 是 Prompt；$y_w$ 中的 $w$ 来自 **winner**，表示人类更偏好的回答；$y_l$ 中的 $l$ 来自 **loser**，表示被拒绝的回答。因此训练数据表达的关系就是 $y_w\succ y_l$：**在同一个 Prompt $x$ 下，我们希望模型更加偏好 $y_w$，而不是 $y_l$。**

注意，这和 SFT（Supervised Fine-Tuning，监督微调）已经不太一样。SFT 只有一个目标回答 $y$，告诉模型“这个回答应该被生成”；而 DPO 同时看到 $y_w$ 和 $y_l$，学习的是一个**相对偏好关系**：前者应该比后者获得更高概率。

问题就在于：怎么把“$y_w$ 比 $y_l$ 更好”变成一个可以反向传播的 Loss？

### 2. 从 RLHF 目标到 DPO

先回到 PPO-RLHF 背后的基本优化目标。我们希望 Policy 获得更高 Reward，但又不能偏离 Reference Policy 太远，可以写成：

$$
\max_\pi\ \mathbb E_{y\sim\pi(\cdot|x)}[r(x,y)]-\beta D_{\mathrm{KL}}(\pi(\cdot|x)\Vert\pi_{\mathrm{ref}}(\cdot|x)).
$$

这里每一部分分别表示：

$\pi(y|x)$ 是我们正在训练的 Policy 在 Prompt $x$ 下生成回答 $y$ 的概率；$r(x,y)$ 是这个回答获得的 Reward；$\pi_{\mathrm{ref}}(y|x)$ 是冻结的 Reference Policy；$D_{\mathrm{KL}}$ 衡量当前 Policy 与 Reference Policy 的分布距离；$\beta$ 控制 Reward 与 KL Constraint 之间的权衡。

整个目标表达的就是：**一方面希望生成高 Reward 的回答，另一方面又要求 Policy 不要为了追 Reward 而无限偏离原来的模型。**

这个优化问题有一个非常关键的结果：它的最优 Policy 可以写成

$$
\pi^*(y|x)=\frac{1}{Z(x)}\pi_{\mathrm{ref}}(y|x)\exp\left(\frac{r(x,y)}{\beta}\right).
$$

这里 $\pi^*(y|x)$ 是满足上面 RLHF 目标的最优 Policy；$\pi_{\mathrm{ref}}(y|x)$ 是 Reference Model 原本给回答 $y$ 的概率；$\exp(r(x,y)/\beta)$ 根据 Reward 对这个概率进行重新加权；而 $Z(x)$ 是 **Partition Function（配分函数 / 归一化常数）**，作用只是保证所有回答的概率最后加起来等于 $1$。

这个式子有一个非常重要的含义：**最优 Policy 相对于 Reference Policy 提高了多少概率，本身就包含了 Reward 信息。**

把这个式子重新整理，可以得到：

$$
r(x,y)=\beta\log\frac{\pi^*(y|x)}{\pi_{\mathrm{ref}}(y|x)}+\beta\log Z(x).
$$

这里 $\frac{\pi^*(y|x)}{\pi_{\mathrm{ref}}(y|x)}$ 表示最优 Policy 相对于 Reference Policy 对这个回答的概率提升程度；取 $\log$ 后得到 Log Probability Ratio（对数概率比）；再乘上 $\beta$，就可以恢复这个回答对应的 Reward，只差一个与回答 $y$ 无关的 $\beta\log Z(x)$。

这一步就是 DPO 真正关键的地方：

**Reward 可以用 Policy 相对于 Reference Policy 的概率变化来表达。**

于是我们就有机会把显式的 Reward Model 从训练公式中拿掉。

### 3. Bradley–Terry 偏好模型

接下来还差一步：我们的数据并没有直接告诉我们 $r(x,y_w)=8$、$r(x,y_l)=3$，它只告诉我们 **$y_w$ 比 $y_l$ 更好**。

为了把这种成对偏好转成概率，可以使用 **Bradley–Terry Model（Bradley–Terry 偏好模型）**：

$$
P(y_w\succ y_l|x)=\sigma(r(x,y_w)-r(x,y_l)).
$$

其中 $P(y_w\succ y_l|x)$ 表示在人类偏好中选择 $y_w$ 而不是 $y_l$ 的概率；$r(x,y_w)-r(x,y_l)$ 是两条回答的 Reward 差；$\sigma(z)=\frac{1}{1+e^{-z}}$ 是 Sigmoid Function。

这个式子的直觉非常简单。如果 $r_w-r_l$ 很大且为正，Sigmoid 输出就接近 $1$，意味着 $y_w$ 很明显优于 $y_l$；如果两者 Reward 差不多，输入接近 $0$，那么 $\sigma(0)=0.5$，表示模型无法明显区分二者；如果反过来 $r_w<r_l$，概率就会低于 $0.5$。

现在把前面得到的 Reward 表达式分别代入 $r(x,y_w)$ 和 $r(x,y_l)$。

对于 chosen response：

$$
r(x,y_w)=\beta\log\frac{\pi_\theta(y_w|x)}{\pi_{\mathrm{ref}}(y_w|x)}+\beta\log Z(x).
$$

对于 rejected response：

$$
r(x,y_l)=\beta\log\frac{\pi_\theta(y_l|x)}{\pi_{\mathrm{ref}}(y_l|x)}+\beta\log Z(x).
$$

两者做差以后，最关键的事情发生了：**$\beta\log Z(x)$ 完全抵消。**

于是 Reward Difference 可以直接写成：

$$
r_w-r_l=
\beta\log\frac{\pi_\theta(y_w|x)}{\pi_{\mathrm{ref}}(y_w|x)}
-\beta\log\frac{\pi_\theta(y_l|x)}{\pi_{\mathrm{ref}}(y_l|x)}.
$$

这时候公式里已经没有 Reward Model 了。

### 4. DPO Loss

最终把这个 Reward Difference 放进 Bradley–Terry Model，并最大化“chosen response 胜过 rejected response”的概率，就得到标准 DPO Loss：

$$
L_{\mathrm{DPO}}(\theta)=
-\mathbb E_{(x,y_w,y_l)}
\left[
\log\sigma\left(
\beta\log\frac{\pi_\theta(y_w|x)}{\pi_{\mathrm{ref}}(y_w|x)}
-
\beta\log\frac{\pi_\theta(y_l|x)}{\pi_{\mathrm{ref}}(y_l|x)}
\right)
\right].
$$

这个公式先不要整体看，把里面拆成两个量。

第一项

$$
\beta\log\frac{\pi_\theta(y_w|x)}{\pi_{\mathrm{ref}}(y_w|x)}
$$

表示：**当前 Policy 相对于 Reference Policy，对 chosen response $y_w$ 提高了多少偏好。**

第二项

$$
\beta\log\frac{\pi_\theta(y_l|x)}{\pi_{\mathrm{ref}}(y_l|x)}
$$

表示：**当前 Policy 相对于 Reference Policy，对 rejected response $y_l$ 提高了多少偏好。**

两者相减以后得到一个 **Preference Margin（偏好间隔）**：

$$
h_\theta=
\log\frac{\pi_\theta(y_w|x)}{\pi_{\mathrm{ref}}(y_w|x)}
-
\log\frac{\pi_\theta(y_l|x)}{\pi_{\mathrm{ref}}(y_l|x)}.
$$

DPO 希望这个 Margin 越来越大，也就是要求：**相对于 Reference Model，当前 Policy 应该更加提升 chosen response，并更加压低 rejected response。**

随后 $\sigma(\beta h_\theta)$ 把这个 Margin 转换成 $0\sim1$ 之间的偏好概率，而外面的 $-\log$ 则把它变成标准的 Binary Cross-Entropy 风格训练目标。

如果当前 Policy 已经明显更偏好 $y_w$，那么 $\sigma(\beta h_\theta)$ 接近 $1$，Loss 接近 $0$，Gradient 也会逐渐变小；如果当前模型反而更偏好 $y_l$，那么这一概率很低，Loss 会很大，Gradient 就会强烈推动模型纠正。

所以 DPO 最核心的一句话就是：

**PPO-RLHF：Preference → Reward Model → Reward → RL → Policy。**

**DPO：Preference → 直接比较 Policy 对 chosen / rejected 的相对概率 → Policy。**

它没有凭空取消“Reward”这个概念，而是利用 RLHF 最优解，把 Reward **隐式地吸收到 Policy 与 Reference Policy 的概率比里面**。因此有时会定义一个 **Implicit Reward（隐式奖励）**：

$$
\hat r_\theta(x,y)=\beta\log\frac{\pi_\theta(y|x)}{\pi_{\mathrm{ref}}(y|x)}.
$$

DPO 真正做的就是让 $\hat r_\theta(x,y_w)>\hat r_\theta(x,y_l)$。

这样一来，Reward Model、Critic、GAE、在线 Rollout 和 PPO Clipping 都不再是标准 DPO 训练所必需的。训练数据只需要 $(x,y_w,y_l)$，再加一个冻结的 Reference Model，就可以像普通监督学习一样直接做 Forward、算 Loss、Backward。

## 8. GRPO

前面的 PPO 和 DPO 实际上走向了两条不同的路线。PPO 保留了完整的在线强化学习过程：Policy 生成 Rollout，Reward 给出反馈，Critic 估计 Value，再利用 Advantage 更新 Policy；DPO 则进一步简化了偏好对齐，把固定的 Preference Data 直接转化成一个监督式 Loss，从而不再需要在线 Rollout、Reward Model、Critic 和 GAE。

对于数学、代码、推理等任务，Reward 往往可以由 Verifier 直接获得。我们当然也可以把这些 Reward 转换成 Preference Pair，再继续使用 DPO；但这样等于先把一个天然存在的标量 Reward 转换成 chosen/rejected 数据。另一种更直接的思路，是保留在线强化学习：让当前 Policy 持续生成新的 Rollout，直接根据这些 Rollout 得到的 Reward 更新 Policy。

于是问题变成了：能不能保留 PPO“生成 → 获得 Reward → 更新 Policy”的在线强化学习结构，同时去掉训练成本较高的 Critic？
这就是 GRPO 的出发点。
这就是 GRPO（Group Relative Policy Optimization，组相对策略优化）的核心出发点。

PPO 中之所以需要 Critic，是因为我们不能只知道一条 Response 得到了 Reward $r$，还需要判断这个结果相对于“当前 Policy 正常情况下能够做到的水平”究竟好多少。Critic 通过 Value Function $V_\phi(s)$ 估计这个 Baseline，然后得到 Advantage。

GRPO 换了一种方法。对于同一个 Prompt $x$，不再只生成一条 Response，而是一次生成 $G$ 条 Response：$y_1,y_2,\ldots,y_G$，然后分别得到 Reward $r_1,r_2,\ldots,r_G$。

既然这些 Response 都来自**同一个 Prompt、同一个当前 Policy**，那么这一组 Reward 的平均水平本身就可以用来近似“当前 Policy 面对这个 Prompt 时通常能够做到什么程度”。因此可以定义组内平均 Reward 为 $\mu_G=\frac{1}{G}\sum_{j=1}^{G}r_j$。

这样，我们甚至不再需要训练一个 Critic 去预测 Baseline。对于第 $i$ 条 Response，只需要看它的 Reward 相对于组平均值高还是低。最简单的 Group Relative Advantage（组相对优势）可以写成 $\hat A_i=\frac{r_i-\mu_G}{\sigma_G}$，其中 $\sigma_G$ 是这一组 Reward 的标准差。

这里的逻辑和前面的 Advantage 完全是接上的。如果 $r_i>\mu_G$，那么 $\hat A_i>0$，说明这条 Response 比当前 Policy 对同一个 Prompt 的平均表现更好，之后应该提高它的概率；如果 $r_i<\mu_G$，那么 $\hat A_i<0$，说明它比平均水平更差，应该降低它的概率。除以 $\sigma_G$ 则是为了把不同 Prompt 下 Reward 的尺度归一化，避免某些 Reward 数值范围特别大的 Prompt 主导训练。

所以 GRPO 最关键的一步，可以直接和 PPO 对照来看：**PPO 是 `Critic → Value Estimate → Advantage`；GRPO 是 `同一 Prompt 多次 Rollout → 组内 Reward 统计 → Advantage`。**


### 1. Policy Update

得到 Group Relative Advantage 以后，GRPO 后面的 Policy Update 就重新接回了 PPO。也就是说，**GRPO 真正替换掉的是 PPO 中 `Critic → Value Estimate → GAE → Advantage` 这一部分，而不是 PPO 的 Clipping 机制。**

对于第 $i$ 条 Response 中第 $t$ 个 Token，仍然计算当前 Policy 与生成这批 Rollout 时的 Old Policy 之间的 Probability Ratio（概率比）。为了避免和前面的 Reward $r_i$ 混淆，这里把 Ratio 记作 $\rho_{i,t}(\theta)$：

$$
\rho_{i,t}(\theta)=
\frac{\pi_\theta(y_{i,t}\mid x,y_{i,<t})}
{\pi_{\theta_{\mathrm{old}}}(y_{i,t}\mid x,y_{i,<t})}.
$$

它和 PPO 里的 $r_t(\theta)$ 是完全同一个东西：如果 $\rho_{i,t}=1$，说明这个 Token 的概率没有变化；大于 $1$ 说明当前 Policy 提高了它的概率；小于 $1$ 则说明降低了它的概率。

区别在于，这一次用来决定更新方向的已经不是 Critic 和 GAE 算出来的 $\hat A_t$，而是前面通过组内 Reward 得到的 $\hat A_i$。

因此，对于一条 Response 来说，如果它的 Reward 高于同组平均水平，那么 $\hat A_i>0$，这条 Response 中实际生成出来的 Token 整体都会受到提高概率的推动；如果 $\hat A_i<0$，则整体受到降低概率的推动。

然后 GRPO 和 PPO 一样使用 Clipped Objective（裁剪目标）限制更新幅度：

$$
L_{\mathrm{GRPO}}
=
\mathbb E\left[
\min\left(
\rho_{i,t}(\theta)\hat A_i,\,
\operatorname{clip}(\rho_{i,t}(\theta),1-\epsilon,1+\epsilon)\hat A_i
\right)
\right].
$$

这里其实没有新的机制。前面 PPO 中已经讲过：Advantage 决定概率应该提高还是降低，Probability Ratio 衡量 Policy 到底改变了多少，而 Clipping 防止一次更新走得过远。GRPO 完整继承了这一部分。

因此现在可以非常清楚地看到 PPO 和 GRPO 的区别：

**PPO：Rollout → Reward → Critic → GAE → Advantage → Clipped Policy Update。**

**GRPO：同一 Prompt 生成多条 Rollout → Reward → Group Normalization → Advantage → Clipped Policy Update。**

两者真正发生变化的地方，就在 **Advantage 从哪里来**。PPO 用一个额外训练出来的 Value Function 估计 Baseline；GRPO 直接用同一个 Prompt 下这一组 Response 的实际表现估计 Baseline。后面的 Policy Gradient 和 Clipping 逻辑则基本保持不变。

### 2. KL Constraint

不过 GRPO 还有一个前面已经出现过很多次的组件：**Reference Policy（参考策略）**。

即使组内 Advantage 能告诉模型哪些 Response 应该被强化，如果只追求 Reward，Policy 仍然可能逐渐偏离原来的语言模型。例如在数学任务中，模型可能找到某些能够骗过 Reward Function 的特殊输出方式，或者为了最大化正确率而逐渐破坏原本的语言能力。

因此 GRPO 通常仍然保留一个冻结的 Reference Policy $\pi_{\mathrm{ref}}$，并加入 **KL Divergence（Kullback–Leibler Divergence，KL 散度）**惩罚，大致可以把整体目标理解为：

$$
L
=
L_{\mathrm{GRPO}}
-
\beta D_{\mathrm{KL}}(\pi_\theta\|\pi_{\mathrm{ref}}).
$$

前面的 $L_{\mathrm{GRPO}}$ 负责推动模型获得更高 Reward，后面的 KL 项负责限制 Policy 不要离 Reference Policy 太远，$\beta$ 则控制这种约束的强度。PDF 给出的基础 GRPO 目标也是“PPO 风格的 Clipped Update 减去 KL Penalty”这一结构。:chatgpt-content-reference{index="1"}

这里尤其要注意：**Reference Policy 依然不是 Critic。** GRPO 去掉的是负责预测 Value 的 Critic；Reference Policy 仍然可以存在，因为它承担的是另一项工作——约束当前 Policy 的变化范围。

到这里，GRPO 最基本的算法其实已经完整了。一次训练循环可以概括成：**取一个 Prompt → 当前 Policy 生成 $G$ 条 Response → Verifier / Reward Function 分别打分 → 组内归一化得到 Advantage → 使用 PPO-style Clipping 更新 Policy → 用 KL Constraint 限制 Policy 偏离 Reference Policy → 更新后重新生成新的 Rollout**。
